1 · Verdict

The idea is right and several subsystems are genuinely excellent. The office itself is not yet trustworthy to leave running.

Five structural gaps recur across every dimension: the autonomy loop and the human-approval path are not wired the way the docs describe; the app can destroy its own work (force-removed worktrees, non-atomic writes, a supervisor that blocks on git); the inner security boundaries lag the very good ingress code; nothing the test suite proves is enforced in CI; and the hive protocol has no acknowledgement, retry, verification, or merge — and only one of eleven engines gets the whole protocol.

8 Critical 12 High 16 Medium 11 Low 24 Keep as-is
SecurityMixed
Ingress is better than most products (hire allowlists, SSRF guard, Slack HMAC, webhook decoys, broker). Inner boundaries are not: PTY input is unsanitised, navigation is unguarded, fs/git root is renderer-chosen, Slack/webhook secrets sit in plaintext, Electron is end-of-life.
ReliabilityWeak
Sophisticated recovery where someone was bitten (sleep/wake, PTY identity guard), but an isolated agent's crash force-deletes its work, the registry/config are written non-atomically, and hive.commit() can freeze the whole supervisor.
Hive protocolMixed
Transport is solid (single writer, router, one-gate typing). Semantics are missing: no ack, no retry, no dead-letter, no result verification, no merge primitive, and wake-ups live in the UI process.
Renderer / UXMixed
The terminal pool and the automation-safety gate are excellent. But "an agent needs you" has no surface — approvals are unsubscribed, blockReason is never rendered — and a single throwing panel white-screens the app.
Tests · CI · releaseWeak
283 tests exist and zero run in CI; eight test files are not in any script; CONTRIBUTING says there is no suite; no log file, no crash reporter; Windows builds unsigned; the release-link gate that a real outage motivated is not wired in.
Memory · KGMixed
Condensation's verify() is the best "never trust the model" code in the repo. Recall is a cold Python spawn (not "milliseconds"), the semantic index never shrinks, and the condense session runs with permissions bypassed and web tools enabled on agent-authored text.

2 · Fix first

Eight Critical findings — most are under ten lines to fix

Ranked by impact per line of change. "Verified" means I read the cited code myself this session, not just the audit summary.

C1Critical

Any teardown of a git-isolated agent force-deletes its uncommitted work

Where
src/main/index.ts:449-458 (teardownPty) → src/main/git.ts:258 git worktree remove --force. The comment literally says "Normal agents keep the immediate force-remove"; only ephemeral workers get the safety gate.
What happens
teardownPty runs on explicit kill, on natural PTY exit (index.ts:568), on breaker stop (index.ts:1132), and on account-failover respawn. An isolated agent works for an hour, its CLI crashes or hits a usage limit → the worktree is removed with --force, untracked files and dirty changes are gone. The failover feature shipped in PR #2 takes this path too for isolated agents.
Fix
Route the non-worker branch through the existing gate: call worktreeHasUnintegratedWork() (git.ts:269, already tested) and keep the worktree when it returns keep — the same shape as finalizeWorkerWorktree. ~5 lines.
Verified first-handEffort: minutes
C2Critical

Any agent, Slack message or webhook can type raw keystrokes into another agent's terminal

Where
src/renderer/src/hooks/useHive.ts:118 wraps multi-line hive text in bracketed paste (ESC[200~ … ESC[201~) with no sanitisation; hive.normalize() (hive.ts:1176-1192) applies no control-character filter; the terminal work-order path (useHive.ts:146-170) is always multi-line.
What happens
A message body containing the literal bytes ESC[201~ closes the paste early; everything after arrives as keystrokes, including \r which submits. Into a coding CLI that is prompt injection framed as if the human typed it; into a custom-command shell it is direct command execution. Reachable from any agent's outbox, from Slack text and from webhook message. It defeats the whole "who may type into a terminal" model in docs/message-queue.md.
Fix
One guard at the single choke point, before the wrap in submitToPty: remove any \x1b[20[01]~ and strip C0 controls except \n/\t. Two .replace() calls.
Verified first-handEffort: minutes
C3Critical

Registry, task ledger, config and account-pool state are written non-atomically — a crash mid-write erases the floor

Where
src/main/hive.ts:1968 writeJson is a bare writeFileSync (the atomic atomicWriteJson sits three lines below and is used only for inbox delivery); it persists registry.json and tasks.json. src/main/config.ts:602 persistConfig is the same, and it is rewritten every heartbeat beat and mission tick just to stamp lastFiredAt. src/main/accountPool.ts:128-136 likewise.
What happens
Power loss / OOM-kill during a write → truncated JSON → readJson/readConfig swallow the parse error and return defaults: god id, every agent's cwd/provider/session, the whole kanban, harnessHome, Claude accounts, webhooks and missions are silently gone and the app reboots into onboarding.
Fix
writeJson → call atomicWriteJson; persistConfig and accountPool.save → tmp + renameSync (mirror roster.ts:149-151, which already does it right). Three one-liners. Then stop rewriting config on every beat by moving lastFiredAt into the existing PersistStore.setKv.
Verified first-handEffort: minutes
C4Critical

The human-in-the-loop gate is instruction text, not enforcement: permissions are bypassed by default on every engine

Where
src/main/config.ts:424 autoMode: true → commandForAutoMode appends --permission-mode bypassPermissions (claude/grok), --dangerously-bypass-approvals-and-sandbox (codex), --yolo (qwen/crush), --dangerously-skip-permissions (agy). The per-agent settings.json the hive writes (hive.ts:876-915) has no permissions.deny block. HIVE.md §2.3 and PROTOCOL.md both state "tool-permission prompts are the HITL gate".
What happens
A worker runs rm -rf, git push --force, or curl | sh with nothing in the way. The only enforcement point, control.toolDecision at PreToolUse, is operator-initiated and default-off. Spend/scope/destructive "escalation" exists only as prose in Michael's prompt.
Fix
Ship a standing permissions: { deny: [...] } list (destructive git, rm -rf, sudo, credential paths) in the hive-authored per-agent settings — it applies under bypassPermissions and costs one object literal. Make autoMode visible on the agent card and in onboarding rather than silent.
Verified first-handEffort: hours
C5Critical

Autonomy lives in the UI process: the Stop-hook drain was removed, and wake-ups, delivery and account failover all run in the renderer

Where
src/main/hooks.ts:211-221 returns {} on Stop ("never turn unread hive mail into a forced continuation"); hive.drainForStop (hive.ts:1056) is referenced only by comments and one test; cursor.json is created and never written. Wake nudge = useHive.ts:636-659 (4 s poll), delivery = effect #4, failover executor = useHive.ts:1146-1230 with a closure-local re-entrancy set.
What happens
Close the window (macOS keeps the app alive), reload the renderer, or crash a panel → no mail moves and a mid-switch failover leaves the agent killed and never respawned ("switching…" forever). This is upstream issue #151. HIVE.md, PROTOCOL.md and the codex/agy preset comments still advertise "Stop→drain works natively".
Fix
Move the kill→respawn failover and the inbox wake into main (main already owns spawnAgentCore and the idle handshake ptyManager.idleFor()); keep the renderer's draft/picker gate as a veto it reports up. Either restore a guarded Stop-drain (no draft + not stop_hook_active) or delete drainForStop, the cursor and the four doc claims. This is also the prerequisite for a tray/headless mode and remote access (#167).
Verified first-handEffort: days
C6Critical

Mail to an unknown recipient vanishes and is logged as delivered

Where
src/main/hive.ts:1197 deliver() returns silently when the inbox dir is missing ("logged by caller"); the caller routeMessage (hive.ts:1283) unconditionally appends {kind:'message'} and flies the envelope animation. canReceiveInbox(undefined) falls back to the claude preset → true (agentProvider.ts:546-548), so an unknown id passes every guard.
What happens
Michael mails oscar-old from a pre-restart transcript; the message evaporates, the log says sent, Michael waits forever. Upstream issue #183.
Fix
deliver() returns a boolean; on false log {kind:'undeliverable', reason:'unknown-agent'} and bounce to god with the full body — the bounce pattern already exists three times in the same function.

C7Critical

CI runs zero tests; eight test files are unreachable; CONTRIBUTING tells people the suite does not exist

Where
.github/workflows/ci.yml has typecheck (macOS only) and build (continue-on-error: true); no test job. package.json has no test script; test:focused hand-lists 33 of 42 files — breaker, webhook-endpoints, slack, kg-core, agent-provider, transcript-usage, voice-messages, realtime-findcard never run. C8Critical

End-of-life Electron rendering agent-authored content, with no navigation guard, sandbox: false, and a window-open handler that opens any URL scheme

Where
package.json pins electron ^32.2.0 (installed 32.3.3, Chromium 128 — outside Electron's latest-3 support window, no CVE backports). src/main/index.ts:2230-2233 setWindowOpenHandler calls shell.openExternal(url) with no scheme check (the sibling app:openExternal at :3886 correctly restricts to https). No will-navigate handler anywhere; webPreferences.sandbox: false (:2157) with a ~160-channel preload that includes pty:spawn. MarkdownPreview's click guard only intercepts click, so a middle-click (auxclick) on an agent-authored link reaches the open handler with the raw href.
What happens
A renderer compromise via agent-written markdown hands an attacker the full bridge; a crafted file:/ms-msdt:/smb: link is opened by the OS.
Fix
In createWindow: will-navigate → preventDefault unless same URL; open handler → https-only then deny; flip sandbox: true (the preload imports only electron). ~6 lines now; schedule the Electron bump (38+) with electron-builder@26 and a re-rebuild of node-pty/better-sqlite3.

H1High

fs:* and git:* IPC are not sandboxed to an agent's directory — the renderer chooses the root

Where
src/main/index.ts:3211-3232 pass the renderer's root straight to listDir/readFileText/readFileBinary/writeFileText; every git:* handler takes an arbitrary cwd. safeJoin (src/main/fs.ts:14-20) confines rel to whatever root was named and is textual (no realpath, so an in-root symlink escapes). Fix
One shared assertManagedRoot(p) built from registeredRepos + harnessHome + live PTY cwds, used by all ~20 handlers; realpathSync both sides in safeJoin.

H2High

Network and secret hygiene: LAN-bound public servers, plaintext Slack/webhook secrets shipped to the renderer, an unauthenticated hook socket, a tunnel that cannot be closed

Where
src/main/webhook.ts:244 and src/main/slack.ts:179 server.listen(port) with no host → all interfaces (the sibling broker and reply server correctly pass '127.0.0.1'); tunnelmole has no close handle, so stop() leaves the public tunnel up (comment at slack.ts:166). src/main/config.ts:602 writes slackSigningSecret, slackBotToken, webhookSecret, webhookTriggers[].secret to config.json in plaintext with no mode, and ipcMain.handle('config:get') (index.ts:3102) returns them to the renderer unredacted — while integrations.ts already has a safeStorage + 0o600 store. src/main/hooks.ts:79-116 trusts payload.agent_id from any local connection (can hijack --resume ids, poison the cost ledger, clear breaker state). Bind both servers to 127.0.0.1 (two string args). Move the four secret fields into the safeStorage store and redact them in config:get. H3High

hive.commit() blocks the main thread on git, per message — and two growing files are committed into the hive repo

Where
src/main/hive.ts:2014-2029: spawnSync git with an 8 s timeout (:1978), five attempts, sleepSync = Atomics.wait on the main thread (:190-193); called from send(), the router tick, writeTasks(), ensureAgent(), setArchived(). .gitignore seed (:505) omits log.jsonl (append-only, 14 writers, never rotated) and backups/ (a full copy of every memory.md on every condense attempt, reflect.ts:202). clearStaleLock (:2032) deletes any index.lock older than 10 s — less than the 8 s git timeout plus antivirus on Windows.
What happens
Worst case on a locked repo ≈ 80 s of frozen supervisor: no IPC, no PTY bytes forwarded, hook shims time out, the UI beachballs. Happy path still serialises a git add -A per hive message. The repo-growth pathology is the one untrackCostLedger was written to fix for a sibling file; the fix was not generalised.
Fix
Debounce commits behind a 5 s trailing timer, make the retry async, timeout 2 s, two attempts; add log.jsonl and backups/ to the ignore seed and reuse the git rm --cached pass; rotate log.jsonl at ~8 MB; raise the stale-lock threshold to 60 s and skip while a git child is in flight; logTail reads the last 64 KB instead of the whole file.
Verified first-handEffort: half a day

H6High

Stale per-agent state survives teardown: a respawned agent is instantly paused, telemetry accumulators grow forever, preserved worktrees leak on quit

H10High

The protocol has no acknowledgement, reply deadline, retry, dead-letter, result verification, or merge primitive — and the god's only spawn mechanism is undocumented to it

Where
requires_reply is set (hive.ts:1188) and enforced by nothing; the only ACK protocol in the repo is closing-time's; hop-cap overflow drops the message (hive.ts:1210-1215) though HIVE.md promises escalation. act:'done' is terminal by design — no reviewer. git.ts has no merge/rebase path at all while the god prompt says "own branch integration". 7 · Keep as-is

What is already excellent

Several parts of this codebase are better than the equivalent in most commercial agent products. They are worth naming so nobody "cleans them up".

  • The one-gate PTY writer and the automation-safety gate (docs/message-queue.md, terminalPool.ts:327-345) — reads xterm's real buffer to clear a phantom draft, with a deliberately asymmetric failure mode and the reasoning written down.
  • terminalPool.ts as a whole — one Terminal per PTY, re-parented hosts, WebGL leasing against Chromium's ~16-context cap, DOM fallback and recovery.
  • Hire import (shared/hire.ts) — default-deny flag allowlist, cmd.exe-aware model regex, https-only homepage, import that only pre-fills.
  • The SSRF guard (main/hire.ts) — BlockList subnet math, v4-in-v6 de-mapping, manual redirects re-validated per hop, streamed byte cap.
  • Slack and webhook ingress — HMAC over the raw body before parsing, 5-minute replay window, decoy endpoints so unknown ids and wrong secrets are indistinguishable, auth before body buffering, two-tier rate limits.
  • The integration broker — loopback bind, per-worker capability tokens never persisted, header-shadowing protection, manual redirects so credentials cannot follow off-origin.
  • Analytics allowlist (main/analytics.ts:44-59) matches TELEMETRY.md line for line, plus DO_NOT_TRACK.
  • Realtime voice key handling — the OpenAI key stays in main; the renderer gets only an ephemeral client secret.
  • reflect.ts verify() — backup → LLM → seven structural checks → atomic rename; every failure path leaves the original byte-for-byte; idempotent.
  • Transcript reader (transcript.ts:213-338) — incremental parse keyed on size+mtime, newline-boundary offsets, bounded cache, tail-only reads.
  • PTY session identity guard (pty.ts:677-706) — kills the kill-then-respawn-same-id race that would spray a dead process's bytes into a fresh TUI.
  • The Windows npm-shim decoder (pty.ts:200-302) — pure, testable, three historical shim shapes plus direct-exe, refuses anything not fully understood.
  • Worker worktree GC safety (git.ts:269-327) — keep on dirty, ahead, or unanswerable; catches squash merges. (Just not yet applied to normal agents — C1.)
  • Sleep/wake recovery (index.ts:4878-4911) — re-arms missions, triggers, beats and the router with fire-once semantics for overdue work.
  • db.ts migrations — user_version + migration in one transaction, WAL, busy timeout, "never edit a shipped migration".
  • providerAutomation.ts — a total record over every provider with a shipped-binary citation per entry and honest nulls.
  • The proxy-bridge tier — synthesising lifecycle events from observed LLM traffic to bring a hookless CLI into the protocol is genuinely novel.
  • ASK ME / humanQA — the question stays on the card, the answer patches the card and mails god, dismissal preserves history.
  • Closing Time — a real ACK-and-wait shutdown protocol with timeout and live progress.
  • Ephemeral workers — isolated worktree, per-worker token cap, idle reap, stale-done guard, safe teardown. The strongest orchestration primitive in the app.
  • Dark-mode token reasoning (tokens.css:97-171) — identified ink-300 as the structural token, measured every ramp step, added --cth-on-accent.
  • Roster mirrored to disk because localStorage is origin-partitioned, with "an empty file must never win over populated localStorage".
  • The floor's clickable props (calendar → triggers, boards → tasks, ASK ME → human, clock → quit) — a real information-architecture idea.
  • Secret redaction at the IPC boundary (hive.ts:243-270) with a lockstep test — it just needs to import the real function.
