<objective>
Make DAEMON-05's prerequisite true: `stop()` genuinely closes the public tunnel, proven by a request
to the public URL failing after stop rather than by the absence of an error.

Purpose: DAEMON-05. **D-13 changes what this work is.** Both servers carry a source comment saying
the tunnel cannot be closed — *"tunnelmole() resolves with a URL STRING and nothing else … There is
genuinely no handle to capture"* (`slack.ts:158-161`, `webhook.ts:224-227`). That sentence is
accurate **about the library call** and false about the capability. Run the same tunnel as a child
process and the OS process handle **is** the disposer. So this plan does not work around a vendor
limitation; it deletes a false claim and the code that made it true.

Three things ship together because they are one seam: the tunnel that closes (`tunnel.ts`), the
binary it closes over (`cloudflared.ts`), and the enable path that guarantees it is never up by
accident (`config.ts` + `index.ts` + `preload`). The two byte-identical `openTunnel` bodies — verified
identical by `diff` this session, not eyeballed — collapse into one helper, and the
`{ tunnelStillOpen }` return that only existed to admit the old defect is deleted rather than left as
a permanently-`null` field documenting a lie.

Output: two new electron-free modules, two servers with no tunnel code of their own, a config default
that is off, an IPC + preload surface plan 02-10 renders, a unit gate that runs offline on three
platforms, and one live check that is deliberately not part of `npm test`.
</objective>

**The child-process shape to copy wholesale: `hive.ts:1281-1345` `startProxyBridge`.** Four properties
are load-bearing and are copied verbatim in kind: the `settle` idempotence latch; **never** `inherit`
on stdio; `on('error')` and `on('exit')` both settling so a dead child never hangs the promise; and an
**unref'd** hard-ceiling timer. Three deliberate divergences, each with a reason:

1. **`stdio: ['ignore', 'pipe', 'pipe']`** — cloudflared writes its banner to **stderr**, and the URL
   must be matched on either stream.
2. **Match a regex over the accumulated buffer, not `indexOf('\n')`.** cloudflared prints the URL
   inside a box-drawn banner, so a newline-delimited parse of the first line finds a box border. Cap
   the buffer (a few KB is plenty) so a chatty child cannot grow memory before the timeout fires.
3. **Keep draining both pipes after settling.** A piped stream nobody reads fills the OS pipe buffer
   and blocks the child forever; cloudflared logs continuously for the life of the tunnel. This is the
   single most likely way this feature "works in the test and wedges in the app".

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| The public tunnel origin → the loopback port it forwards to | This is the whole surface. Everything bound on that one port becomes internet-reachable the moment the child starts. The tunnel must forward to exactly the one `127.0.0.1:PORT` of a secret-gated server, never `0.0.0.0`, never a hostname a resolver could redirect. |
| Cloudflare's GitHub release → a process this app spawns | A ~52 MB binary with **no publisher checksum file**. GitHub's `assets[].digest` is same-origin integrity, not provenance. Verified bytes prove only that nobody substituted the file after the digest was recorded. |
| The cloudflared child's own update channel → the verified binary on disk | cloudflared self-updates by default. Left on, it replaces the digest-verified binary at runtime with one nobody verified, inside a process this app spawned. |
| `stop()` → the public hostname's lifetime | Before this plan the hostname outlived `stop()` and the source admitted it. After it, the OS process handle is the disposer — and a leaked child on any error path silently restores the old defect. |
| The child's stdout/stderr → logs and agent terminals | The tunnel URL is effectively a capability address for the floor. `inherit` would write it into an agent's terminal and into the app log. |
| `tunnelEnabled` → every other feature's config write | DAEMON-05's off-by-default clause is only as strong as the number of code paths that can set the key. |
