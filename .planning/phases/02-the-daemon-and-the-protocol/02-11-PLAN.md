already-fail-closed tier branch without changing one character of its predicate, a config migration
that drops floor-wide write/secret consent rather than silently carrying it forward, three IPC
channels that never let a secret or a secret ref cross into the renderer, and the preload `platform`
field UI-SPEC Rule C-1a needs before any card is built.

**The channel, in one sentence (D-25, RESEARCH §5, three runs).** `mcpServers` inside a `--settings`
file is ignored **unconditionally** — run 2 exists specifically to rule out `--strict-mcp-config` as
the suppressor, and it is not. `--mcp-config <file>` spawns the server with and without the strict
flag, and with **no interactive approval prompt** in print mode. `claude --version` on this machine
is `2.1.236 (Claude Code)`.

**⚠ `claude mcp list` IS NOT A PROBE.** It ignores both `--settings` and `--mcp-config` and lists the
operator's own configured servers, so it returns a confident green against a completely broken
channel. The probe is a marker-writing stdio server under `claude --print`, or nothing.

**`--strict-mcp-config` is a POLICY DECISION and this plan makes it: it goes ON.** Without it the
operator's own `~/.claude.json` servers ride into every hive agent — an agent running with
`--permission-mode bypassPermissions` silently gains every tool the operator configured for
themselves, with the operator's tokens, while the card shows only the granted set. That is precisely
the class of claim this phase deletes: a UI describing a capability set that is not the real one.
The cost is real and must be recorded, not buried: **an operator who relied on their personal MCP
servers inside hive agents loses them**, and the remedy is granting the catalog equivalent per agent.
This is a behaviour change, it belongs in the SUMMARY under a heading plan 02-12 can grep, and the
source comment at the flag site says so.

**The consent split (D-27), exactly.** Safe-readonly stays **floor-wide** (`config.mcpDefaults`,
already built and already surfaced by `McpDefaultsSettings.tsx`). `write` and `secret` become
**per-agent** (`config.mcpAgentGrants[agentId][mcpId]`). The merge is one pure function, and the
predicate `buildDefaultMcpServers` already runs is untouched:

> `const consented = cfg?.[e.id]?.enabled; const enabled = consented ?? e.defaultEnabled;`
> `if (!enabled) continue; if (e.tier !== 'safe-readonly' && consented !== true) continue;`

Feed that same `cfg` a map assembled per agent and per-agent consent is done. Rewriting the predicate
is how this becomes a security regression with a green suite.

**The secret path (D-28), and what must NOT be built.** `integrations.ts` already ships `setSecret`
(`:118`), `getSecret` (`:126`, MAIN-INTERNAL ONLY), `hasSecret` (`:150`), `deleteSecret` (`:156`),
`deleteSecretsWithPrefix` (`:173`) and `writeSecretBlob`'s `mode: 0o600` temp+rename (`:108`).
**No second store is built and none of these functions is modified.** `secretRefFor(id)`
(`src/shared/integrations.ts:91`) returns `` `int:${id}` `` — so an MCP grant's ref is
`int:mcp:<agentId>:<mcpId>`, which `resetConfig`'s existing `cfg:` sweep does **not** reach. That is
#10 again with a different prefix, and this plan closes it in the same file.

**⚠ `getSecret` imports electron. `hiveProvisioning.ts` and `hive.ts` must stay electron-free** —
02-01 asserts zero `electron` imports in the new module, and five test files load `hive.ts` under
`node --test`. The secret resolver is therefore an **injected function** on `ensureAgent`'s options

breaks the whole test surface this phase just paid for.

**⚠ `<agentDir>/mcp.json` is the first file this app writes that contains a live credential in
plaintext, inside a directory that a git committer commits.** Two mitigations, both required:
