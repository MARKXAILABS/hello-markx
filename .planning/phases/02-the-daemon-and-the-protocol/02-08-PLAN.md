**⚠ CONTAINMENT IS PROVED OVER THE COMMIT RANGE, NEVER OVER THE WORKING TREE.** Every "file X was not
edited" criterion in this plan uses `git diff --name-only "$BASE"..HEAD -- <files>`, which must print
nothing. **`git status --porcelain` is not acceptable for this and has been removed from every site it
occupied**: it reports only *uncommitted* changes, so the moment a task commits it is empty regardless of
what was edited, and a standalone commit touching only an unowned file is invisible to it — which is
precisely the edit these criteria exist to catch. Nor do the two per-commit containment criteria close
that hole: they iterate `git log "$BASE"..HEAD -- <owned files>`, so a commit that touches **no** owned
file is never enumerated. Verified this session against real SHAs, both directions — fixed endpoints so
it re-runs identically after the tip moves:

```

    src/renderer/src/components/TasksKanban.tsx src/preload/index.ts

$ git diff --name-only 17bf26d^..17bf26d -- test/hive-protocol-v2.test.cjs \
    src/renderer/src/components/TasksKanban.tsx src/preload/index.ts
test/hive-protocol-v2.test.cjs                     # the FAIL shape — a real edit IS detected
```

(`37f43b2` is the sha the rest of this file was measured at; `02dea58` was the tip when this block was
written; `17bf26d` is `git log -1 -- test/hive-protocol-v2.test.cjs`, the last commit that really touched
it. The second command is the whole point: `git status --porcelain` returns nothing for that commit.)

**And `$BASE` must be bound INSIDE every range-bound criterion.** An unbound one does not fail loudly; it
passes silently, because an empty left-hand side means `HEAD`. Measured this session:

```

^02dea58f04016298fdd191cd2ebc1fc1b2b3540f          # i.e. HEAD..HEAD, an empty range
```

The same silent pass applies to `git diff --stat "$BASE"..HEAD -- package.json package-lock.json`, which
is why the D-06 criteria carry the guard too.

Every range-bound criterion below — containment, `package.json`, and the two `git diff | grep -c`
negatives — therefore opens with the **BASE-GUARD**, and this is what that phrase means wherever it
appears:

```
BASE=<B-sha>; test -n "$BASE" && git rev-parse --verify -q "$BASE^{commit}" >/dev/null \
  || { echo "UNBOUND BASE — CRITERION FAILS"; false; }
```
