<objective>
Move ownership of the delivery queue and its drain into main, so a message composed in the UI reaches
its recipient with the window closed.

Purpose: FLOOR-02's second and largest half. The drain loop is ~150 lines in
`useHive.ts:819-968`, but its own comment (`:806-818`) explains why it stayed in the renderer: *"it
holds messages the RENDERER produced … it lives in renderer state, and main has no view of it."*
So moving the loop requires moving the **queue** — this is a data-ownership migration, not a code move.

**Do not start by porting 150 lines.** The graded criterion is *"with the app window closed, a
message composed in the UI still reaches its recipient's inbox and is typed into that agent's
terminal"*, and that is satisfied by a persisted **main-side queue that the renderer appends to** —
much smaller than relocating all five producers. Task 1 defines that minimum in writing before any
code moves.

Output: a main-owned persisted queue, one IPC enqueue channel, the pure policy relocated to
`src/shared/` so both processes can use it, the renderer's drain effect deleted, and the veto
contract intact.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer producers → main-owned queue (IPC) | A new IPC channel that causes text to be typed into an agent's terminal. Payload validation at the handler is mandatory. |
| main queue drain → agent PTY | ADR-0001's one gate for PTY writes. A second writer here is a correctness and a safety defect. |
| human draft (veto) → delivery suppression | The one renderer responsibility that must survive the migration. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-P08-01 | Tampering | the new enqueue IPC handler | mitigate | Validate the payload shape and the target agent id at the `ipcMain.handle` boundary; return `{ok:false, error}` rather than throwing. Follow the `useHive.ts:658-660` convention that neither side trusts IPC blindly. |
| T-P08-02 | Tampering | two writers to one terminal | mitigate | The main-side drain routes through the SAME single PTY write gate the tick already uses (ADR-0001); the renderer's drain is deleted, not left as a fallback. |
| T-P08-03 | Repudiation | a message delivered twice or silently dropped during the ownership handover | mitigate | Route through the existing `seenSet` dedup, not beside it; an idempotency test (enqueue-and-tick twice writes once) is an acceptance criterion. |
| T-P08-04 | Denial of service | the durable queue growing without bound | mitigate | Prune delivered entries; bound the persisted file the same way the hive's other jsonl files are bounded. |
| T-P08-05 | Elevation of privilege | a renderer producer enqueuing to an agent it should not address | mitigate | The handler resolves the recipient against the live roster in main rather than trusting the renderer's id blindly. |
| T-P08-06 | Repudiation | the human's veto silently lost in the migration | mitigate | The veto path is explicitly NOT migrated, is asserted by a unit test, and is re-checked by the operator checkpoint. |
</threat_model>
