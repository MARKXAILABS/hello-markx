**Invocation form, standardised for this whole plan — and it is not a style preference.**
`01-VALIDATION.md:28` and plan `01-23:514` both require the *gate* to be pasted literally as
`npm run lint`, and both forbid bare `npx eslint` (it can fetch an unpinned ESLint from the registry
instead of running the pinned local install). This plan therefore uses exactly two forms and no others:

- **`npm run lint`** — every gate, every `<verify>` tag, the CI step. One definition, byte-identical
  locally and in CI, and the string plan `01-23` greps for.
- **`./node_modules/.bin/eslint …`** — only the two runs that need per-invocation flags the script
  cannot carry: the whole-tree *measurement* (`--max-warnings 999 --format json`, deliberately not the
  gate's `0`) and amendment D's *per-file* resolver (`<file> --no-inline-config --format json`, one file
  at a time). This is the same local pinned binary `npm run lint` executes — `node_modules/.bin` is on
  the PATH of an npm script — so it is not "bare `npx eslint`" and cannot reach the registry. Written
  out longhand rather than via `npm run lint -- --max-warnings 999`, which would leave two conflicting
  `--max-warnings` values on one command line and decide the gate by last-flag-wins.

- The file's run reports a `react-hooks/exhaustive-deps` message -> the directive is **live**: keep it.
- The file's run reports none -> the directive suppresses nothing: **delete it**, and record the pasted
