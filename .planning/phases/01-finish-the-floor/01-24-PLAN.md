## What changed from revision 1, and why

Revision 1 was rejected by a six-gate red team. Three of its instructions were actively dangerous.
They are corrected here, and the corrections are the point of the plan — do not restore the originals.

1. **The second base is GONE.** Revision 1 resolved relative targets against
   `join(hiveRoot, 'agents', agentId)` as well as the registry cwd. `protectedPathDenial` feeds EVERY
   shell word of every Bash command through `denyReason`, so that base turned `../node_modules/.bin/tsc`
   into `<hive>/agents/node_modules/.bin/tsc` — inside `<hive>/agents`, owner `node_modules ≠ a-1` —
   and DENIED it with a message naming an agent that does not exist. `../shared/lib.ts` and
   `../packages/core` behaved the same. The base added zero security value: the `owner !== agentId`
   branch already ALLOWS an agent its own directory, so joining onto the agent's own hive dir can only
   ever produce a false deny. Task 1 now carries `../`-shaped negative controls so this cannot come back.

2. **`payload.cwd` is now READ, not banned.** Revision 1's threat model called it spoofing. That
   reasoning is inverted for a DENY-LIST: the vouched bases are still checked, so an EXTRA candidate
   base can only ever produce an EXTRA deny, never an extra allow. A lying `cwd` costs the attacker a
   deny and gains it nothing; a truthful `cwd` is the only thing that catches a `cd`-relative write.
   It is filtered by `isAbsolute()` like every other candidate.

3. **The byte cap and the idle timeout now fail CLOSED.** Revision 1 `destroy()`d the connection.
   Every shim does `c.on('error', () => process.exit(0))` (`src/main/hive.ts:3669`, `:3734`, `:4117`),
   and this repo states the consequence in its own words at `test/net-binding.test.cjs:279`: *"the
   shims exit 0 on a connect error, and exit 0 with no stdout is `allow`."* A `Write` to
   `<hive>/bin/cth-hook.cjs` padded past the cap would have gone from DENIED today to ALLOWED after the
   fix, with the attacker choosing the size. Every abnormal exit from this listener now writes an
   explicit deny response first.

4. **The doubled-side-effect premise is retracted.** Revision 1 instructed the executor to paste
   "a doubled cost sample, a doubled `breaker.recordToolUse` repeat count, a second `drainAtStop`
   cursor advance and a second toast" into the SUMMARY as established fact. Measured at HEAD this
   session, every shipped shim emits exactly ONE payload per connection —
   `src/main/hive.ts:3652`, `:3759`, `:3798`, `:3861` use `c.end(...)`; `:3665`, `:3730`, `:4113` are
   write-then-read-then-exit. **No shipped shim can double-handle.** The real defect is latent and is
   stated as such in Task 2. Do not write the retracted claim into any SUMMARY.

5. **Behaviour case "`cd $HIVE_ROOT && cat >> bin/cth-hook.cjs` is DENIED" is withdrawn.** No candidate
   base can satisfy it: Claude Code's `cwd` is the SESSION cwd, not the post-`cd` cwd, and the gate sees
   a command string, not a shell. It is recorded as a named residual on the existing ceiling comment
   instead of shipped as an unreachable acceptance criterion.

## What changed in revision 4, and why

Round 3 was returned NOT CLEAN by three lenses. The headline is that **task 2 shipped, for the third
consecutive round, a bound whose failure mode is ALLOW**. Everything below is a correction, and the
corrections are the point of the revision.

11. **`server.maxConnections` and the aggregate in-flight byte budget are DELETED. They may not come
    back in any form.** Node enforces `maxConnections` inside `onconnection`, in C++, **before** the
    `'connection'` event is emitted: it closes the client handle and returns. The user handler never
    runs, so the module-level deny constant this task creates can never be written on that path. Round-3
    lens B measured it on this host: the over-cap peer sees `connect -> end -> close` and reads **zero
    bytes**. Follow this repo's own chain — `resp` stays empty, `c.on('end', () => done(0))` fires,
    `process.exit(0)` with no stdout, and `test/net-binding.test.cjs:279` states the consequence in the
    repo's own words: *"exit 0 with no stdout is `allow`."* An attacker buys a **floor-wide ALLOW with
    N idle sockets and zero payload bytes** — strictly cheaper than the memory exhaustion the bound was
    added to prevent. Revision 3's own behaviour case for it (*"assert what the over-limit connections
    receive (a deny, then a close)"*) is unsatisfiable by construction: they receive nothing.

    Three rounds, three bounds, one root cause:

    | round | mechanism | how it became an ALLOW |
    |---|---|---|
    | 1 | `conn.destroy()` on cap-cross | discards pending writes, peer gets ECONNRESET, shim exits 0 |
    | 2 | idle timeout sized ABOVE the shim's 5 s budget | the deny is written to a peer that already exited 0 |
    | 3 | `server.maxConnections` | Node destroys the socket inside `onconnection`, 0 bytes received, shim exits 0 |

    > **The design rule this listener must be built against: the shim's failure mode is ALLOW.
    > Any mechanism that closes, destroys, refuses or starves a connection is a BYPASS, not a control.
    > The only admissible bound is one that delivers an explicit `permissionDecision: 'deny'` to a peer
    > that is still connected to read it.**

    The aggregate in-flight byte budget fails the same rule from the other side. Round-3 lens B showed
    it has no eviction and no per-peer accounting: a peer that never closes holds budget indefinitely,
    and once the budget is exhausted **every** new connection on the floor is denied — a self-sustaining
    outage that also turns every `Stop` on agy and grok into `{decision:'deny'}` (`hive.ts:3722`,
    `:4103`). Fail-closed-total-outage is not better than fail-open; it is the other half of a choice
    the attacker gets to make. Both mechanisms are gone.

    **What remains, and it is enough for one connection.** The per-line byte cap and the idle timeout
    close the loop between them: a connection that stops sending is reaped by the idle timeout, with an
    explicit deny; a connection that keeps sending crosses `HOOK_LINE_MAX` and is denied. There is no
    third state in which a peer holds buffered bytes indefinitely, so exposure is
    `concurrent connections x HOOK_LINE_MAX` **with forced turnover**. The unbounded quantity that
    remains — the NUMBER of concurrent connections — is recorded as an accepted residual with an owner
    (T-P24-12) and its arithmetic is published in the SUMMARY. It is not traded for an allow.

12. **DELETED BY REVISION 5.** Revision 4 required the win32 normaliser to run to a fixed point on BOTH
    sides of the resolve step. That instruction was correct *for the mechanism it belonged to*, and the
    mechanism is gone — see item 18. Do not reintroduce `canonicalSpelling` in any form.

13. **The `.native` fallback stays DELETED, and `realpathSync` is no longer load-bearing at all.**
    Revision 3 mandated a fallback to the JS `realpathSync` on the stated ground that *"`.native` throws
    where the JS one does not on at least one shape"*. Round-3 lens B hunted that shape across 22 path
    forms plus an exclusive-lock case and found **zero divergences in that direction**. The fallback
    rested on an unreproducible premise, its body was — in revision 3's own words — *"exactly the old,
    non-canonicalising behaviour"*, and no behaviour case drove it. Under revision 5 the resolver is not
    the control any more: `realpathSync.native` survives for exactly ONE job, dereferencing a leaf
    symlink before the identity walk, and even that is only needed because `statSync` follows a
    symlinked *ancestor* on its own. Do not add a JS fallback.

14. **DELETED BY REVISION 5.** Revision 4's DoS answer was (b) refuse to RESOLVE non-local network
    paths before resolution. That mechanism is gone; the re-argued decision is
    `## The DoS decision, re-argued under identity` below, and B4-04 disappears with it.

15. **The leaf-symlink clause is pinned by a real leaf symlink, and revision 3's assurance was false.**
    Revision 3 wrote *"Do NOT skip the leaf ... case 8 of the `:250` test pins it"*. It does not: case
    8's `hop` is a **directory** symlink and the target is `hop/cth-hook.cjs`, so under the
    memoise-the-directory scheme the memo resolves `hop` to `<root>/bin` and the case is DENIED whether
    or not the leaf is canonicalised — lens B ran the skip-the-leaf variant and it stayed green. The
    false sentence is deleted and behaviour group C adds a real leaf symlink. Re-measured under the
    identity shape this session with a **junction** (`mklink /J`, which needs no elevation, unlike
    `symlinkSync`): a directory link in the ancestor chain is closed by `statSync` alone, with no
    resolver, for both an existing leaf and a not-yet-created one. The LEAF link still needs
    `realpathSync.native`, which is why item 13 keeps it.

16. **The cost table is re-measured for the shape actually being shipped.** Revision 4's table measured
    a resolver that no longer exists. The identity shape has a different profile — it stats the whole
    ancestor chain instead of realpath-ing one directory — so every number is re-measured in this
    session and the old table is deleted rather than inherited. The headline: an ordinary 2616-word
    heredoc costs **721 ms at HEAD and 23 ms under identity**, and the cap's own worst case at
    `HOOK_CANDIDATE_MAX = 500` is **114 ms**, not revision 4's 98 ms. The constants are unchanged; the
    justification is re-derived, not copied.

17. **The FIVE-FAMILY LISTS ARE DELETED.** Revision 3 let `truths`, `<success_criteria>` and the
    behaviour cases drift apart, and revision 4 fixed the drift by making three copies of the same
    enumeration. Round 4 then found four more members of it. **An enumeration kept consistent in three
    places is still an enumeration.** There is now one truth about identity and one behaviour group
    that runs a measured battery against it; nothing in the source, and nothing in the frontmatter,
    names a spelling.

## What changed in revision 5, and why

Round 4's security lens returned `01-24` NOT CLEAN with four blockers, and the finding underneath all
four is a single sentence: **the fix was an enumeration of a hostile input space, and enumerations of a
hostile input space do not converge.** Four rounds of spelling canonicalisation produced 17 named
bypasses; round 4 found eight of them on its own (own LAN IP, Tailscale IP, WSL vEthernet IP,
`\\0--1.ipv6-literal.net\C$`, `C:../../bin/cth-hook.cjs`, `<root>\bin.\cth-hook.cjs`,
`\\?\Volume{GUID}\…`, `\\?\GLOBALROOT\Device\HarddiskVolume3\…`) and observed that the `::1` entry in
the plan's own local-host set is **dead code**, because a colon is not legal in a UNC host component.
The answer is not a longer list.

18. **`canonicalSpelling` IS DELETED. The comparison is (dev, ino) IDENTITY.** `fs.statSync` returns
    `dev` and `ino`. Two paths that name the same filesystem object have the same `(dev, ino)`
    **regardless of spelling** — that is not a heuristic, it is what a file identity is. Measured this
    session on the operator's host against a real hive tree, with a real write through each spelling
    and an `existsSync` check on the plain path afterwards: **thirty spellings, every one ALLOWED at
    HEAD, every one DENIED under identity**, including all eight of round 4's new ones, and including
    a **hard link**, which four rounds of this plan recorded as irreducible. The full table is in
    `<interfaces>`. `dev`/`ino` for the hard link are literally equal
    (`dev=3222877229 ino=24769797950806710 nlink=2` on both entries), which is why three lines close
    what no amount of canonicalisation could.

    **One control replaces the entire enumeration.** There is no host set, no prefix rewrite table, no
    fixed-point iteration and no share-shape test in the shipped fix. The one place a NAME is still
    compared is inside a directory whose identity has already been established — see item 19 — and
    that is a space of three literal strings (`bin`, `.git`, `agents`), not of spellings.

19. **The hard part is non-existent paths, and it is solved by identifying the nearest EXISTING
    ancestor.** `statSync` throws ENOENT on a file that does not exist yet, and the gate must still
    DENY a write that would CREATE `<hive>/bin/cth-hook.cjs`. So: climb to the nearest existing
    ancestor, then walk UP from it comparing `(dev, ino)` against the cached identities of
    `<hive>/bin`, `<hive>/.git`, `<hive>/agents`, the socket (POSIX) **and the hive root itself**. The
    hive-root identity is what makes a fresh hive safe: when `bin/` does not exist yet there is no
    identity to match, so the walk reaches the hive root — an object main has already identified — and
    the un-created tail below it is a plain, case-folded name comparison against three literals.
    Measured this session on a hive whose `bin/`, `.git/` and `agents/` are all absent: creating
    `<hive>/bin/cth-hook.cjs`, `<hive>/BIN/cth-hook.cjs`, `<hive>/bin./cth-hook.cjs`,
    `<hive>/.git/hooks/pre-commit`, `<hive>/agents/b-1/settings.json`, the `\\localhost\C$\…` spelling
    of the first and the `\\?\` spelling of the first are **all DENIED**, while `<hive>/README.md`,
    `<hive>/binary/x.ts` and `<hive>/agents/a-1/notes.md` are all ALLOWED.

20. **It fails CLOSED, and that is a named behaviour change.** If the climb reaches the volume root
    without a single successful `stat`, main cannot say what the path names, and the answer is DENY.
    On a local drive this branch is unreachable — the volume root always stats — so it fires for
    exactly two classes: an unmapped drive letter, and an unreachable UNC host. **`\\nas.invalid\share\project\file.ts`
    therefore changes from ALLOWED (revision 4, and HEAD) to DENIED**, and the group-B negative control
    changes with it. That is deliberate: the failure mode is a false deny with a reason naming
    identification, on storage that could not have accepted the write anyway. Say it in the SUMMARY;
    do not let a reviewer discover it.

    The same rule handles the one filesystem where identity is not available: if the hive root's own
    `ino` is 0 — a volume with no stable file ids, exFAT and some network filesystems — **every**
    candidate denies with a reason naming the volume, rather than silently degrading to the string
    comparison that every one of these 30 bypasses lives in. That is an outage for that operator, it is
    loud, and it is the correct direction. It is T-P24-17 and it is written down.

21. **B4-02, the drive-relative target, is a FRAMING bug and identity does not close it.** Say so
    plainly rather than claiming the new control covers everything. `path.win32.isAbsolute('C:../../bin/cth-hook.cjs')`
    is **false**, so the string takes the `join(base, target)` branch, and `path.win32.join` eats the
    `C:` as an ordinary segment — the gate measures one directory too deep and allows, while Windows
    measures from the process's **per-drive current directory** and writes the real file. Main cannot
    see that directory; there is no frame to measure against. So the target is refused: on win32, a
    target matching a drive letter followed by a colon and NOT a separator, which also contains a
    separator, is DENIED with a reason saying main cannot frame it. Measured this session, both
    spellings (`C:..\..\bin\cth-hook.cjs` and `C:../../bin/cth-hook.cjs`) are ALLOWED at HEAD, land the

## The DoS decision, re-argued under identity

**The finding is unchanged, and one new measurement changes the argument.** One resolution of a path on
an unreachable network host blocks the Electron **main** thread synchronously. Re-measured this session,
at HEAD, on the operator's host, with the live routing table captured alongside (it is in
`<interfaces>`): `\\10.255.255.1\share\a\b.ts` -> **21 020 ms**, `\\192.0.2.1\…` -> **21 034 ms**, and
the three hosts revision 4 published as **0-1 ms** now block for **21 026 / 21 021 / 21 037 ms**.

**Revision 4's 0-1 ms row does not reproduce, and it is deleted.** Round 4 filed this as W4-03 and
re-measured all five at ~21 s; this session reproduces round 4, not revision 4. The row was
load-bearing for *"no count cap can be calibrated for both"*, so that sentence goes with it. The
structural conclusion is unaffected and in fact simpler: the cost is **uniformly** ~21 s per fresh
unreachable host, and no count cap greater than one is safe against it.

**The new measurement, which is what decides the design.** `fs.statSync` costs the SAME 21 s as
`realpathSync` on a host nothing has touched yet — measured on three hosts untouched this session:
`10.44.33.22` **21 030 ms**, `192.0.2.77` **21 032 ms**, `172.20.111.9` **21 040 ms** — and the second
call against the same host costs **1-3 ms**, because Windows caches the failure. So:

- switching from `realpathSync` to `statSync` neither adds nor removes this cost;
- the cost is **per distinct unreachable host, once**, not per candidate.

**Decision: (b) is DELETED. The bound is the wall-clock budget, and its ceiling is the residual.**
Revision 4's (b) refused to RESOLVE a candidate that was still a UNC path whose host was not in the
local set. Under identity that mechanism cannot be kept:

- Its predicate is the same enumeration this revision exists to delete. `\\192.168.31.97\C$\…`,
  `\\100.99.217.4\C$\…` and `\\172.28.64.1\C$\…` are all **this machine**; any name test that skips
  the stat for them re-opens B4-01 the moment the operator gets another adapter. There is no name test
  that is both cheap and correct, which is the whole finding.
- Its stated justification — *"this changes COST, never VERDICT"* — was already false for the device
  namespace (B4-04), and under identity it would be false for every local alias as well.
- It is no longer needed for what it actually bought. With a per-payload memo and
  `HOOK_RESOLVE_BUDGET_MS` checked BETWEEN candidate resolutions, N candidates against dead storage
  cost **one** blocking resolve and then a DENY. `budget + one resolve` is exactly the worst case HEAD
  has today with a single absolute `file_path` of `Z:\x` or `\\10.255.255.1\share\x`. This plan does
  not make it worse, and (b) never removed the `Z:\` half of it anyway.

So the answer is **(a) the wall-clock deadline, alone**, plus **(c) a named residual with an owner**.
On crossing `HOOK_RESOLVE_BUDGET_MS` the answer is **DENY**, with a reason naming the budget — it
degrades to a deny, never to an allow. **Ceiling, and it goes in the comment: a deadline checked
between resolutions cannot interrupt ONE in-flight blocking syscall, so the true worst case is
`budget + one resolve`.** Against N slow candidates it turns `N x cost` into `budget + one cost`; it
cannot do better than one, and it does not pretend to.

**(c) the residual, ACCEPTED, with an owner (T-P24-14).** One blocking resolve, once per payload,
against storage that does not answer — an attacker-supplied unreachable UNC host, a dead
`net use Z: \\dead\share` letter, a disconnected removable volume. **This is pre-existing at HEAD**
(one absolute `tool_input.file_path` of `Z:\x` does it today with no plan applied) and this plan
neither introduces nor multiplies it. It is named in the ceiling comment and in the SUMMARY.

**What was deliberately NOT chosen.** Not a per-candidate resolution timeout: a synchronous `statSync`
cannot be aborted in-process, so it would need a worker thread or a child process — a new IPC surface
and a new failure mode inside the function that decides GATE-01, bought for a residual HEAD already
has. Not `fs.promises.stat`: making `denyReason` async changes `handle()`'s contract and every caller
on the socket, which is a different plan with a different blast radius. And **not a fourth mechanism
that closes a connection** — see item 11.

## Round-5 security corrections — MANDATORY, they override any earlier text in this plan

Round-5 confirmation (`01-REDTEAM5-SEC.md`) verified the identity redesign genuinely closes the
spelling class: 27 spellings ALLOWED at HEAD, DENIED under identity, on NTFS **and** ext4, hard link
included. These four corrections are residue on top of a design that works. Where they conflict with
anything above, THESE WIN.

### C-1 (CRITICAL) — the hard-link check must cover `<hive>/bin` RECURSIVELY, not one level

`readdir` of `<hive>/bin` one level deep misses `<hive>/bin/runtime/`, and that directory is
**arbitrary code execution in every agent**:

- `src/main/hive.ts:645` — `return root ? join(root, 'bin', 'runtime') : null;`
- `src/main/hive.ts:621` writes `<root>/bin/runtime` on bootstrap (the bundled-node trick).
- `src/main/pty.ts` — `withHiveRuntimeFallback()` appends `join(hiveRoot, 'bin', 'runtime')` to the
  PATH of **every agent PTY**.

Round 5 demonstrated it end to end on win32 and ext4: hard link into `bin/runtime/node.cmd` →
`IDENTITY=ALLOWED` → the write lands → the real shim reads `REM PWNED`.

**Required:** when `nlink > 1`, compare the candidate's identity against **every file beneath
`<hive>/bin` recursively**, not `readdir` of its top level. Bound the walk and DENY if the bound is
crossed — a bound that gives up must never degrade to allow. **Delete the sentence mandating that the
SUMMARY and the ceiling say *"the `<hive>/bin` half is CLOSED"*** until this is what ships; with a
one-level readdir that sentence is false.

### C-2 (HIGH) — the un-created-tail rule lists THREE literals; there are FOUR protected paths

The rule names `bin`, `.git`, `agents`. **`sockPath()` is `<hive>/hooks.sock` on POSIX** and it is
protected. Measured on ext4: socket present → correctly identified; socket **absent** → `ALLOWED`.
That window is `socketWatchdogMs = 10_000`, and the source's own comment says *"re-taking is a race we
can lose."* Add the socket's basename as the fourth literal, and add a behaviour case for the
socket-absent window.

### C-3 (HIGH) — the 31st spelling: rooted-relative `\bin\…`

`path.win32.isAbsolute('\bin\cth-hook.cjs')` is **true**, so it takes the measure-one-path branch and
is framed against **main's** cwd drive, while `cmd.exe` frames it against the agent's. Round 5 landed a
real file in the real `bin/` with the hive on a `subst` drive. Same class as B4-02 but NOT covered by
the `driveRelative` predicate, and not named in the ceiling. Extend the framing predicate to
rooted-relative and add both a behaviour case and a ceiling line.

### C-4 (HIGH) — `statSync` must use `{ bigint: true }`

`pathIdentity`'s spec implies a Number `ino`. Measured on this host's live hive paths:
`ino = 24769797950806710`, which is **2750x past `Number.MAX_SAFE_INTEGER` (9007199254740991)**.

direction. Use `statSync(p, { bigint: true })`, compare `BigInt` values, and use `0n` for the
