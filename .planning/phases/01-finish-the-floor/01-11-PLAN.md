<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent workspace files → the hive git repository | An LLM-controlled process writes files that a debounced committer stages with `add -A` and commits without inspection. Git history is durable and hard to redact after the fact. |
| hive git history → anywhere the hive repo is shared or backed up | Once committed, a secret is in every clone and every backup. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-P11-01 | Information disclosure | a secret written by an agent landing in git history | mitigate | Scan `git diff --cached` with the existing `redactSecrets` between `add -A` and `commit`; unstage offending paths and log loudly. Single choke point per ADR-0004. |
| T-P11-02 | Information disclosure | a secret the matcher does not recognise | accept + document | Best-effort matching is the honest ceiling. A test pins the current limit and the SUMMARY states it; the docs must not claim more. GATE-02 (a later phase) covers the distinct problem of the child env. |
| T-P11-03 | Tampering | a second, disagreeing pattern set | mitigate | Reuse `redactSecrets` only. Two matchers that disagree is worse than one imperfect one; widen the single matcher if needed so mail and commits stay consistent. |
| T-P11-04 | Denial of service | the scrub throwing and taking down the debounced committer | mitigate | Every git call is handled with the repo's discriminated-result idiom; a failure logs and degrades rather than throwing out of `flushCommit`. |
| T-P11-05 | Denial of service | scanning an enormous staged diff on every commit | mitigate | Bound what is scanned and state the bound in the code comment; the hive already bounds its own files via `LOG_ROTATE_BYTES` and `UNTRACK_PATHS`. |
| T-P11-06 | Repudiation | a commit silently altered without the operator knowing | mitigate | The scrub logs loudly and the behaviour is asserted by a named test. |
</threat_model>
