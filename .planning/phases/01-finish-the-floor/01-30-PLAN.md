## Correction to the gate note above (orchestrator, round 3)

The note said `verify.cjs` evaluates `contains:` as a **regex**. **That is wrong**, and round-3
lens A caught it. `bin/lib/verify.cjs:314` is:

```js
if (artifact.contains && !fileContent.includes(artifact.contains))
```

`contains:` is `String.includes()` — a **literal substring**. `key_links[].pattern` IS compiled as a
regex (that is where `Invalid regex pattern` comes from). Two different semantics on adjacent fields.

So the real reason `contains: "sock_token[\"']?"` passed at HEAD was **not** regex collapse. It was
the same defect as every other plan's: the trailing `#` evidence comment made `parseMustHavesBlock`
emit `undefined` for the key, and `artifact.contains &&` then short-circuits, **skipping the check
entirely**. Had it parsed, the literal 13-character string `sock_token["']?` appears nowhere, so the
gate would have been correct-but-unsatisfiable — a different defect with the same symptom.

Repointing the gate to `stripLineComments` was still the right fix and is unchanged. Only the stated
reason was wrong, and a wrong reason recorded as measured fact is the defect class this phase exists
to remove — so it is corrected here rather than quietly edited away.
