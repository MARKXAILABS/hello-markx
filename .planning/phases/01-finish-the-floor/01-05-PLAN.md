## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| main process `hive:tasks` IPC → renderer | The renderer must not trust IPC blindly; `useHive.ts:658-660` records the house convention (main filters, and the renderer still validates). Each component's own parser is where that happens and must be preserved. |
| renderer timers → the hive task file on disk | Every poller is a repeated read of one file; the count of readers is a resource concern, not a security one. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-P05-01 | Denial of service | N independent 5-second `hiveTasks()` timers | mitigate | Collapse the five timer sites onto `useHiveTasks`'s single shared interval, which exists only while something is mounted; pinned by `test/repo-claims.test.cjs`. |
| T-P05-02 | Denial of service | unbounded terminal pool / leaked xterm instances | mitigate | Already shipped (`TERMINAL_POOL_MAX = 24`, LRU eviction, roster orphan sweep). This plan audits that every drop path REACHES the sweep and fixes only a path that does not. |
| T-P05-03 | Denial of service | roster re-render per PTY byte | accept (already mitigated) | `store.ts:614-621` returns state unchanged on a non-material patch; policy extracted pure in `agentPatch.ts`. No change — rebuilding it risks regressing tested behaviour. |
| T-P05-04 | Tampering | a component parsing the raw `unknown` payload incorrectly after migration | mitigate | Each component keeps its own existing parser verbatim; the migration is delete-local-state-and-call-the-hook, nothing more. Rendered output must be identical. |
| T-P05-05 | Repudiation | the shared hook silently losing its callers again in a later refactor | mitigate | `test/repo-claims.test.cjs` asserts a minimum caller count, not just the absence of timers. |
