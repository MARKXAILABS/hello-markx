<objective>
Build the day-band CCTab: a fixed-height density band over a wall-clock 24h axis, a native range
scrubber, a day picker, and one merged detail list of the selected bucket's rows — reading from
03-03's `hive:timeline`/`hive:timelineBucket` IPC (which reports `firstTs`, the earliest event
timestamp still stored). Pixi.js and any second WebGL context are refused (D-28); no windowing
library is used or needed, because both lists are structurally bounded (96 columns, one bucket deep,
capped at 200).

`test/renderer-components.test.cjs`'s `renderToStaticMarkup` harness runs with no effects and no state
commits — a component that fetches its data via `useEffect` renders with EMPTY state on the one pass
the test can observe, so any assertion depending on real counts, the gap sentence, or the truncation
`<li>` would silently pass on empty output, or force the executor to downgrade to grepping the source
file (which proves the string exists in the code, not that the branch renders it). This plan gives
`DayBandTab` an explicit, optional data prop the production mount leaves undefined (so real usage is
unaffected — it still fetches via IPC) and the test supplies directly, mirroring 03-08's
`agentView.ts` seeding-seam requirement, so the data-dependent assertions are genuine first-pass
markup.

Purpose: "yesterday is replayable" needs a surface, not only a store. This is that surface, built
entirely from primitives already in the app (a native range input, an SVG of rects, the `Modal`-free
tab-body pattern every other CCTab already uses).
Output: `DayBandTab.tsx` (with its test-injectable data prop), the `TABS` entry, and the one new CSS
block for the scrubber thumb, landed in the CSS file the app actually bundles.
</objective>
