try/catch returning `T | null`, then a SEPARATE sequential loop adding successes IN INPUT ORDER
(never completion order). Parameterize on the per-item async spawn function so `useRestoreTeam.ts`
(spawning `Agent`-shaped restorable entries) and the new team-import path (spawning
`HireManifest`-shaped members) share the identical concurrency/ordering/failure-isolation shape
without sharing the (very different) per-item spawn-argument construction.

src/renderer/src/hooks/useRestoreTeam.ts` returns zero hits.** It reuses each restored agent's

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-03-06a | Elevation of Privilege | a manipulated member row spawning with an unreviewed command | accept | Every member's command is rebuilt LOCALLY via `hireCommandFor` from the provider preset — the manifest can never inject the spawn binary, matching the existing single-hire security model unchanged |

| T-03-06c | Repudiation | a failed member's error being lost/overwritten by a later success | mitigate | Per-member failure copy renders in place on that row per `<behavior>`, never collapsed into one sheet-level toast |
