<objective>
Build one daily digest, delivered three ways in decreasing order of guaranteedness — write a file,
toast a notification, post to Slack — driven by a wall-clock timer that survives sleep/restart and
never routes through `deps.send` (which silently no-ops with no window, exactly the headless scenario
this requirement exists for). Land the timer's `SHUTDOWN_STEPS` entry in the same commit that creates
it, per D-30's own warning about the hang-not-red failure mode. Gate the Slack arm on the SAME toggles
the operator actually sees (`dailyDigest`, `slackEnabled`), not only on the presence of a token and a
channel id — and stamp every arm with the active project's identity, per D-31 (LOCKED).

Purpose: an operator who is not watching the app should still learn what happened yesterday — without
a daily post landing in Slack after they believed they had turned digests, or Slack itself, off. Every
piece of this already has a proven shape in the codebase (`syncContextTriggers`'s timer,
`writeFleetSnapshot`'s never-throws file write, `postSlackReply`'s raw-https POST) — this plan copies
each shape without copying `emitContextTrigger`'s dead-end delivery.
Output: `DIGEST_DEFAULT_HOUR`, `msUntilNextLocalHour`, the digest timer + content builder, correctly
gated `postSlackDigest`, and the Settings toggle with its honest limitation.
</objective>
