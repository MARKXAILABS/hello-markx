roster already writes and cannot drift out of sync the way a hand-authored or LLM-authored file
would — but that promise only holds if the exported file can actually be re-imported. Two gaps close
that loop in this same plan: `HireProvider`'s allowlist was 3 values (`claude`/`antigravity`/`codex`)

stripped member against the validator before writing it, so any other cap (description length, model
character set) could also silently produce an unimportable file.

team@1's only safe producer is export, and "safe" includes "actually round-trips."

```
export function readHireManifestFile(path: string): HireResult {
  try {
    if (statSync(path).size > HIRE_MAX_BYTES) return { ok: false, error: 'manifest too large' };
    const parsed: unknown = JSON.parse(readFileSync(path, 'utf8'));
    return finish(validateHireManifest(parsed));
  } catch (e) { return { ok: false, error: `could not read manifest: ${String(e)}` }; }
}
export type HireResult = { ok: true; manifest: HireManifest } | { ok: false; error: string };
```
The size check runs BEFORE `JSON.parse` — the team branch must preserve that ordering (parse only
after a cheap `statSync` size gate).
