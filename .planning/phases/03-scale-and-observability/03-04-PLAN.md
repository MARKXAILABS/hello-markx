From `src/main/hire.ts`'s `readHireManifestFile` (current, verified this session):
```
export function readHireManifestFile(path: string): HireResult {
  try {
    if (statSync(path).size > HIRE_MAX_BYTES) return { ok: false, error: 'manifest too large' };
    const parsed: unknown = JSON.parse(readFileSync(path, 'utf8'));
    return finish(validateHireManifest(parsed));
  } catch (e) { return { ok: false, error: `could not read manifest: ${String(e)}` }; }
}
export type HireResult = { ok: true; manifest: HireManifest } | { ok: false; error: string };
```
The size check runs BEFORE `JSON.parse` — the team branch must preserve that ordering (parse only
after a cheap `statSync` size gate).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Disk (untrusted team@1 file) <-> main | Same untrusted-input surface `hire@1` already has — a team file is a wrapper of N `hire@1`-shaped members |
| main <-> disk (export write) | Operator-chosen save path via `dialog.showSaveDialog`; write content is derived entirely from the app's own roster, not from renderer input |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-03-04a | Elevation of Privilege | a team@1 member smuggling a shell-metacharacter flag or a raw binary path | mitigate | Every member is delegated, unmodified, through `validateHireManifest`'s existing default-deny `SAFE_FLAG_NAMES`/`FLAG_RE`/`MODEL_RE` allowlists — no parallel, weaker check exists for team members |
| T-03-04b | Information Disclosure | `team:export` leaking `cwd`/`account`/`accountPolicy`/`worktreePath`/`ptyId`/raw `command`/`commandFlags` | mitigate | `stripAgentForExport` picks an explicit ALLOWLIST of fields to include (never a denylist of fields to drop), and this plan's acceptance criteria assert `commandFlags` is never derived from `command` |
| T-03-04c | Denial of Service | an oversized team@1 file (`JSON.parse` memory pressure) | mitigate | `TEAM_MAX_BYTES` (256KB) gates via `statSync` BEFORE `readFileSync`/`JSON.parse`, mirroring the existing single-manifest `HIRE_MAX_BYTES` gate |
| T-03-04d | Tampering | `team:export`'s write path | accept | `dialog.showSaveDialog` is the operator's own OS-native file picker; the write target is always operator-chosen, never renderer-supplied |
</threat_model>
