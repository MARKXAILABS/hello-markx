<objective>
Build the main-process half of SCALE-02's team template: a `hello-markx/team@1` JSON wrapper format
that delegates per-member validation to the existing, hardened `validateHireManifest` unchanged, a
spec-branch in `readHireManifestFile` (BEFORE the validator, per D-17), and the ONLY new IPC channel
this requirement needs — `team:export` — landing with its production caller (the export button) in
this same plan, per D-38. The import-review-sheet UI and the bulk-spawn loop are 03-06, a separate
plan (the import path rides the EXISTING `hire:openFile` channel, so it is not a "new sink" under
D-38's rule).

`team@1`'s only safe producer is export, because export reads the same `PersistedAgent` records the
roster already writes and cannot drift out of sync the way a hand-authored or LLM-authored file
would — but that promise only holds if the exported file can actually be re-imported. Two gaps close
that loop in this same plan: `HireProvider`'s allowlist was 3 values (`claude`/`antigravity`/`codex`)
against 11 real `AgentProvider` engines, so exporting a realistic floor (grok, qwen, opencode, ...)
produced a file the app's own `validateHireManifest` rejected on `provider`; and nothing checked a
stripped member against the validator before writing it, so any other cap (description length, model
character set) could also silently produce an unimportable file.

Purpose: `src/shared/hire.ts` is a finished, security-reviewed single-agent format with no producer;
team@1's only safe producer is export, and "safe" includes "actually round-trips."
Output: the team@1 format, its validator (with a real member cap), the widened-but-still-deny-by-
default provider allowlist, the validate-before-write export stripper, and `team:export` wired end to
end.

From `src/main/hire.ts`'s `readHireManifestFile` (current, verified this session):
```
export function readHireManifestFile(path: string): HireResult {
  try {
    if (statSync(path).size > HIRE_MAX_BYTES) return { ok: false, error: 'manifest too large' };
    const parsed: unknown = JSON.parse(readFileSync(path, 'utf8'));
    return finish(validateHireManifest(parsed));
  } catch (e) { return { ok: false, error: `could not read manifest: ${String(e)}` }; }
}
export type HireResult = { ok: true; manifest: HireManifest } | { ok: false; error: string };
```
The size check runs BEFORE `JSON.parse` — the team branch must preserve that ordering (parse only
after a cheap `statSync` size gate).
