<objective>
Land SCALE-03's storage layer: an `events` SQLite table as migration #3, fed by an injected sink
beside `appendLog`/`appendCostLedger` (never a `PersistStore` import into `hive.ts`), a NEW pure,
loadable aggregation module (`timeline.ts`) that computes day/bucket summaries, and the two
main-process IPC handlers a day-band UI will read from. `log.jsonl` stays as the agent-readable tail;
SQLite becomes the queryable-by-time-range authority. This plan does NOT build the timeline UI —
that is 03-07, which depends on this plan's IPC contract, including `firstTs`.

`index.ts` cannot be loaded by any test in this repo (`electron_1.app.on is not a function` under the
test harness's Electron stub) — three existing test files already document this limit in prose. That
means aggregation logic written directly inside `index.ts`'s handlers is exercised only by grep
assertions an empty stub implementation would also satisfy. This plan puts the actual bucket math,
the detail-row cap, `firstTs`, and argument validation into `src/main/timeline.ts` — a plain,
Electron-free module — so a new `test/timeline.test.cjs` can call it directly and assert real
behavior (96 buckets, envelope filtering, the 312-row truncation case, a malformed-argument
rejection). `index.ts`'s handlers become thin: fetch rows from `persist`/`hive`, hand them to
`timeline.ts`, return the result.

Purpose: nothing in this app can answer "what happened between 9am and 10am yesterday" today —
`logTail()`'s 64KB read is a window, not a time-range query, and cost-ledger.jsonl and log.jsonl are
never joined. This plan makes that answerable without adding a new dependency, and makes the answer
itself testable, not merely grep-shaped.
Output: migration #3, `timeline.ts`, the injected sink, `applyCostRow` as an exported shared function,
and `hive:timeline`/`hive:timelineBucket`.
