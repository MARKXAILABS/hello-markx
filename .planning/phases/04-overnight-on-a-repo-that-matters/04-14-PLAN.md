**Purpose 1 — the contrast defect, and why fixing it here is not the opportunistic edit decision #30
forbids.** `PixelButton.tsx:71-76` renders the `destructive` variant as a `--cth-coral` fill with
`text: 'var(--cth-ink-900)'`. Measured this session: light mode `#1A1320` on `#D96A62` = **5.34:1**, PASS.
Dark mode `#DEDBD6` on `#E08C82` = **1.85:1**, **FAIL — the label is effectively invisible.**
`--cth-on-accent` on the same fill is **7.12:1**. This is *exactly* the failure `tokens.css:90-94` was
written to prevent, quoted verbatim there: *"The accents are LIGHT surfaces in BOTH themes, so this is
dark in both — using ink-900 here inverts with the theme and paints near-white on a pale accent, which is
the one place the theme switch actively hurts legibility."* `--cth-on-accent` exists for this and
`PixelButton` does not use it. **Light mode is byte-identical**: `--cth-on-accent` is `#1A1320`
(`tokens.css:94`), theme-invariant, and light-mode `--cth-ink-900` is the same `#1A1320`. Decision #30
refuses a *cosmetic* token swap inside a security-surface diff; this is a **1.85:1 label on the deny
button of the approval gate this phase exists to build**, and plan 04-18 may not ship the GATE-05 banner
on top of it. One line, its own atomic `fix(...)` commit, the measurement in the commit message.

**Purpose 2 — GATE-03's denial legibility (04-UI-SPEC § S2).** The path already runs end to end; three
things are missing. `BlockReason.command` exists at `store.ts:22` and `BlockedBanner` already renders it
at `:44-59` — **but nothing sets it.** Plan 04-06 made `emitControl` carry the command; this plan spends
it. The summary should name the agent (`Ada's Bash call was refused`) rather than
`` `${tool ?? 'A tool'} was blocked` ``. And the *why* is already correct at `useHive.ts:620` — only the
**fallback** changes.

**Purpose 3 — VIGIL-03's one broken badge site (04-UI-SPEC § S4 rule V-1b).** Of nine `PixelBadge` render
sites, seven carry an agent status, and exactly one is broken: `CommandCenterPanel.tsx:795` renders
`<PixelBadge status={armed ? 'looping' : a.status} />`. While `armed` is set (`:742`: breaker level
`constrained` or `stopped`), **a blocked agent reads `looping` on this roster** — and that badge is the
row's only blocked signal. VIGIL-03's requirement is *"an agent blocked on a prompt is visibly blocked"*;
on this surface, under a tripped breaker, it is not. This is not an opportunistic fix: it is the literal
text of VIGIL-03's acceptance criterion failing on a shipped surface.
