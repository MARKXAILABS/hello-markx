<objective>
The desktop half of GATE-05 and VIGIL-01: the approval banner with its countdown, and the `QUIET` chip.

**Purpose — the banner is not a modal, and that is a decision with a reason.** `BlockedBanner`
(`BlockedBanner.tsx:10`) is **reused, not replaced**: it is already the app's "needs you" surface, already
coral-framed, already renders a `command` line (`:44-59`), already renders `approve`/`deny`/`neutral`
buttons from `reason.actions`, and is already rendered at `AgentDetailPanel.tsx:221` and
`CommandCenterPanel.tsx:236`. `Modal.tsx` traps focus (`:126-132`) and restores it on close (`:104`) —
correct for the MCP consent flow, **wrong for a timed interrupt** that arrives at 3am, auto-resolves in
~two minutes, and can land while the operator is mid-sentence in another agent's terminal.

**ADR-0001 is the hard line.** `docs/adr/0001-one-gate-for-pty-writes.md`: exactly one place types into a
live PTY. `BlockedBanner`'s existing `if (send && agent.ptyId) writePty(...)` path stays for the
PTY-parser-derived reasons it was written for, but **when `askId` is present the answer goes through the
approval IPC and never through `writePty`.** If any part of this plan reaches for `writePty` on an ask, it
is wrong.

**The titlebar constants are load-bearing and this phase invalidates them.** `App.tsx:55-56` pins
`TUNNEL_CHIP_W1 = 833` and `TUNNEL_CHIP_W2 = 783` — two **live-measured, pinpointed-to-the-pixel**
overflow thresholds (the comment at `:50-54` records `783px: no overflow, 782px: overflow`), derived with
the `PUBLIC` chip present and **no second chip**. This plan adds a second chip to that same 36px strip.
**Binding: re-measure both with both chips present, by the same method, and either correct them or add a
third.** Deriving the new value by adding an estimated chip width to 833 is exactly the arithmetic that
produced `01-14`'s zero-width-name defect.

**Output.** The IPC route, the banner's three new behaviours, the chip, and a containment probe run
against base and head.
</objective>
