<objective>
VIGIL-01: nothing happening is itself an event. When no card advances, no mail routes and no spend lands
for longer than a threshold, the operator is told **once**, with what was in flight when it stopped —
**including the case where the god itself died**.

**Purpose, and the trap this plan exists to avoid.** D-23 is emphatic: this is **not** `HEARTBEAT_MISSION`,
and conflating them fails the requirement's hardest clause. Measured at `src/main/config.ts:95-107`:
`enabled: false` (`:104`), `intervalMs: 120_000`, `quietThresholdMs: 300_000` (`:106`), and `to: 'god'`
(`:98`). Its documented job (`config.ts:85-94`) is to *"drop a digest into god's inbox and (if god's PTY is
genuinely idle) nudge it to re-engage anyone stalled"*, and it ships disabled precisely because *"the
heartbeat types into god's PTY."* **A beat addressed to the god cannot report that the god died.** So
VIGIL-01 is a distinct, **operator-directed** watchdog. It may reuse the heartbeat's quiet computation and
its scheduler slot; it may not be the same message. `HEARTBEAT_MISSION` is **read-only** for this plan.

**Where it lives, and why that is the whole design.** D-25: the watchdog cannot live anywhere that dies
with the god. `floor/boot.ts` owns the module-level `let` block (`:150-180`) and the `Floor` interface
(`:97-146`) whose `shutdown` is documented as *"the exact inverse of construction. #34 — ONE list"*. A
`setInterval` created in `bootFloor` and cleared in `shutdown` alongside `fleetTimer` (`:155`) and
`breakerBeatTimer` (`:156`) is the established shape. It survives the god's death because it is not the
god, and it survives a closed window because `floor/headless.ts` boots the same floor with no renderer.

**D-24 — the quiet signal already exists in main; do not add a second one.** `PtySession.lastOutputAt`
(`pty.ts:59`, doc `:54-58`) is *"the most recent byte this PTY emitted"*, and its own doc records that the
heartbeat already reads it for *"floor-quiet detection (an agent printing/thinking counts as activity even
before it writes a hive file)"*. RESEARCH found two further assets CONTEXT.md never names: **`idleFor(id)`
at `pty.ts:940-945`** — the per-PTY silence, already computed — and `outputTail(id)` at `:930`. Combine
`idleFor` with the ledger's last mutation and the router's last delivery for the requirement's three-part
test. Every signal in this plan's `AbsenceWatchdogDeps` is a read of something that already exists.

**And it needs nothing from the RECORD track.** RESEARCH § Open Question 3 recommends the watchdog read
the **ledger `rev`** (`hive.ts:2118-2123`, bumped on every mutation) plus `appendLog`, rather than
`tool_calls` or a per-card `updatedAt`. That dissolves S-3 and S-5 and lets the VIGIL and RECORD tracks
run fully independently under `use_worktrees: false`. **Take it** — one integer that already exists, and
it is exactly "did the ledger change".

**The `index.ts` collision dissolves too.** The Collision Map scores `index.ts` two-way (GATE-05's
`openPhoneAsks` at `:1219-1236`, VIGIL-01's wiring at `:4763-4795`) — 3,527 lines apart. But it notes:
*"If the plan keeps the watchdog entirely inside `boot.ts` and reuses the already-wired `deps.notify`,
`index.ts` needs no VIGIL-01 edit at all and this collision dissolves."* **Do that.** `index.ts` is not in
this plan's `files_modified` and must not appear in its diff.

```ts
// src/main/floor/watchdog.ts — electron-free.

export interface QuietSnapshot {
  /** Duration, never a timestamp. 04-UI-SPEC rule G-3: the client's clock is not
   *  the floor's clock, and a deadline sent to a client is optimistic by its skew. */
  sinceMs: number;
  /** Cards in `doing` at the MOMENT OF THE TRANSITION, with their assignees. */
  inFlight: Array<{ id: string; title: string; assignee?: string }>;
  /** True when the god's own PTY is among the dead. Changes the copy entirely. */
  godDead: boolean;
}

export interface AbsenceWatchdogDeps {
  now(): number;
  /** Max idleFor across live agent PTYs (pty.ts:940-945). */
  ptyIdleMs(): number;
  /** hive.ts:2118-2123 — bumped on EVERY ledger mutation. One integer. */
  ledgerRev(): number;
  /** Epoch ms of the last appendLog write of any kind. */
  lastEventAt(): number;
  /** Epoch ms of the last telemetry cost sample (telemetry.ts:571). */
  lastSpendAt(): number;
  doingCards(): Array<{ id: string; title: string; assignee?: string }>;
  godAlive(): boolean;
  /** The three D-25 channels. All three, once per quiet edge. */
  notify(a: { title: string; body: string }): void;
  publishQuiet(s: QuietSnapshot | null): void;   // the phone's sibling field + the desktop chip
  push(a: { title: string; body: string; taskId: string }): void;
}

export class AbsenceWatchdog {
  constructor(deps: AbsenceWatchdogDeps, opts?: { thresholdMs?: number });
  /** Called from the boot timer. Idempotent per tick. */
  tick(): void;
  /** Current snapshot, or null when the floor is moving. */
  current(): QuietSnapshot | null;
}
```

Why two accessors rather than one: the phone's half runs **in main** (`webhook.ts` composes the response
from a getter `index.ts` supplies) and needs a synchronous read; the desktop's half runs **in the
renderer** and needs a push. `hookServer` solved the approval seam with a `Floor` member because both its
consumers are in main; the quiet snapshot has one consumer on each side of the IPC boundary, so it needs
one of each. Both are declared here, in wave 3, because wave 3 is the last wave in which a single plan owns
`boot.ts`.
