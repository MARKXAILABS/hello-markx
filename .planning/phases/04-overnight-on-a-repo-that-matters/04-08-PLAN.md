<objective>
VIGIL-02: a card whose owner died goes back on the board within a minute, naming who dropped it and where
their branch is — instead of reading as in-progress forever.

**Purpose.** `teardownPty` is now `src/main/floor/lifecycle.ts:222-252` (moved from `index.ts` by Phase 2's
STRUCT-01). It runs `integrationBroker.revoke` → `breaker.forget` → `control.forget` → `telemetry.forget`
→ `hive.stopProxyBridge` → `hive.setArchived(agentId, true)` at `:232` — and, exactly as the requirement
says, **touches the ledger not at all**. Everything VIGIL-02 needs is already in scope within a few lines
(D-26): the dropping agent is `agentId`, in hand at `:224`, and *where their branch is* comes from
`worktreeHasUnintegratedWork(wtPath, baseBranch)` (`git.ts:334`, called at `lifecycle.ts:200`), which
already returns keep/branch/detail and already logs a preservation path.

**D-27: "within a minute" is satisfied synchronously, not by a sweep.** `teardownPty` runs on node-pty's
`onExit`, so the card can be released in the same tick the agent dies — well inside the minute. A periodic
reaper is worth having as a backstop for the case where main missed the exit, but the **primary path is
the teardown itself, and this plan tests that one.**

**L-09 is the constraint that shapes the implementation, and RESEARCH picked the option for us.**
`worktreeHasUnintegratedWork` is `async` and shells git; it is reached only inside `finalizeAgentWorktree`
(`:196-214`), which `teardownPty` fires with `void` at `:247`. **So the branch fact is not available in
the same tick as the card release.** Two ways out:

- (a) release the card synchronously at `:233` naming only *who* dropped it, then patch the branch detail
  from `finalizeAgentWorktree`'s continuation a moment later — two ledger writes, both through
  `bin/task.cjs`, and the minute budget is met by the first;
- (b) release from inside `finalizeAgentWorktree` — one write, but it inherits that function's `try/catch`
  at `:212`, which currently swallows and logs, **so a git failure would silently mean no card release.**

**(a) is the ADR-0003-shaped choice**: when we cannot prove work is safe to discard we keep it — release
first, enrich later, never lose the release to a git error. Take (a).

**Output.** Two ledger writes in `lifecycle.ts`, both through the sanctioned writer, and two tests.
</objective>
