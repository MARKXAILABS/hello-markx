<objective>
GATE-02: bound the blast radius of every agent shell at the one place a PTY's environment is built.

**Purpose.** `src/main/pty.ts:745` is the single `pty.spawn` call, and `:751` opens its env with
`...process.env` before layering `PATH`, `TERM`, `COLORTERM`, `FORCE_COLOR`, the POSIX locale pair, the
per-agent `opts.env`, and finally `HIVE_SOCK_TOKEN` and the OTLP header tokens — the last two deliberately
last "so nothing upstream can shadow it". One choke point, already commented as such, already ordered. The
fix is a **filter applied to the base spread**, not a new mechanism (D-11, RESEARCH § Pattern 1).

**Allowlist, not denylist, and the reasoning is already in the codebase.** The operator's credentials
arrive under names this project does not choose — `AWS_*`, `GH_TOKEN`, `GOOGLE_*`, `ANTHROPIC_API_KEY`,
`OPENAI_API_KEY`, `NPM_TOKEN`, anything ending `_SECRET`, and whatever the next tool invents. Enumerating
an input space someone else chooses is the exact reasoning `hooks.ts:815` already rejects for path
spellings.

**S-7 is why this plan is wave 1.** *"GATE-02 is first or last within the GATE track, never in the
middle — stripping the env is the most likely way to break a working floor, and it must be the change a
live smoke test immediately follows. Mid-wave, every subsequent failure is ambiguous."* This plan is
first, and it carries its own live smoke as its last task. That is why `autonomous: false`: task 3 is a
blocking human verification, and it is adjacent to the change by design, not by accident.

**Output.** `allowFromEnv` in `shellEnv.ts` with a written ceiling, the splice at `pty.ts:751`, an
operator-visible pass-through escape, a both-directions unit test, an extended PTY test, and a live smoke.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator's `process.env` → agent PTY child env | The core boundary. Agents run with permissions bypassed by design (PROJECT.md), so every variable handed across is readable by a prompt-injected model. |
| operator config (`envPassThrough`) → the filter | Operator-editable security configuration. ASVS V14: it must fail safe when malformed. |
| agent shell → its own grandchildren | Out of reach by construction; named in the ceiling. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-ENV-01 | Information disclosure | A prompt-injected agent reading a cloud/git/API credential out of its own env | mitigate | Allowlist at `pty.ts:751`, the single `pty.spawn` choke point; ceiling item (a) names what it does not reach (ASVS V8) |
| T-04-ENV-02 | Denial of service | The filter stripping `PATH` on a machine that spells it `Path`, killing every agent with ENOENT | mitigate | `toUpperCase()` on both sides of every comparison (L-13); a dedicated test case with the mixed-case spelling; the item stays in the ceiling so a future edit cannot silently reintroduce it |
| T-04-ENV-03 | Denial of service | A BYOK engine losing its key and the floor "silently stopping at 3am" | mitigate | Operator-editable `envPassThrough` escape hatch; the live smoke in task 3 is adjacent to the change (S-7); L-04 named in the ceiling |
| T-04-ENV-04 | Elevation of privilege | An overbroad `envPassThrough` re-admitting everything | accept | It is the operator's own knowing choice; ceiling item (c), ACCEPTED, owner: the operator. Malformed input (non-array, non-string members) must not throw — it defaults to `[]` |
| T-04-ENV-05 | Information disclosure | The agent exporting a secret it read from a file, defeating the gate | accept | Ceiling item (a). Out of scope for an env filter by definition; named so it is not read as a guarantee |
| T-04-SC | Tampering | npm/pip/cargo installs | mitigate | No install step; `04-RESEARCH.md` § Package Legitimacy Audit records zero packages proposed |
