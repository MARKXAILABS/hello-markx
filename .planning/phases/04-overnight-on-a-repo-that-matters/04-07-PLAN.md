<objective>
VIGIL-03's detector. Plan 04-03 guarded `delivery.quiesce` against a blocked agent and filtered the wake
nudge; that guard is fed `false` by every caller today. This plan makes `blocked` true when it should be,
**in main**, so the guard becomes reachable and the headless floor works.

**Purpose, and the decisive argument the requirement text predates.** D-29 gives three reasons blocked
detection moves to main, and the second is the one that settles it:

1. **Off-screen coverage.** `src/renderer/src/components/terminalPool.ts:59` has a single `onData` slot
   *"set by whichever view is mounted"*, so renderer detection is mount-scoped by construction. An
   off-screen agent is never marked blocked, so `stopArmDecision`'s guard (`useHive.ts:169`) never fires
   for it — which is D-28's point.
2. **Headless correctness.** Phase 2 delivered a floor that runs with no window
   (`src/main/floor/headless.ts`). A renderer-resident parser **does not exist at all** on a headless
   floor, so *every* agent is undetectable there, not merely the unmounted ones.
3. **Main already sees every byte first.** `proc.onData` at `src/main/pty.ts:826` is upstream of the IPC
   that feeds the renderer, and `PtySession.tail` / `outputTail(id)` (`pty.ts:64-77`, `:930-933`, 256 KiB
   cap at `:77`) is a main-side ring that fills **whether or not a renderer is attached**.

**S-6 is why this is wave 2 and not wave 1.** Guard first (two lines, testable with a fake), detector
second. Reversed, the detector has nothing to feed and the guard's test cannot be written.

**Output.** One shared hint list, main-side evaluation, the renderer reading a state main owns, and a test
that proves detection with no renderer in the process at all.
</objective>
