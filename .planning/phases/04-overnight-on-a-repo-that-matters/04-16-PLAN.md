<objective>
GATE-05's shim half: the bounded wait that times out to **deny**, built as a poll because a measurement
says the obvious alternative is a silent fail-open.

**Purpose.** Plan 04-15 made main answer an ask with a reply that is simultaneously a deny for an old shim
and a `hive_ask` handle for a new one. This plan teaches **`HOOK_SHIM`** — Claude's, codex's and kimi's —
to see the handle and poll. `GROK_HOOK_SHIM` and `AGY_HOOK_SHIM` are left byte-identical: a shim may enter
the loop only on an engine whose PreToolUse timeout this app itself writes (plan 04-15's rule), and for
those two the ask reply's own `permissionDecision: 'deny'` stands, translated by decoders that already
exist.

**L-02 is why this is a poll and not a stream, and it is not a preference.** Measured:
- `HOOK_SHIM` (`hiveTemplates.ts:341-345`): `c.on('data', d => resp += d)`, `c.on('end', () => done(0))`,
  and `done` writes `resp` to stdout verbatim.
- `GROK_HOOK_SHIM` (`:770-784`): `done` runs `JSON.parse(resp || '{}')` over the **whole accumulated
  buffer**; on a parse failure it sets `out = null` and `process.exit(0)` **with no stdout — which is
  allow**.
- `AGY_HOOK_SHIM` (`:364-412`): the same shape.

A "pending" preamble written on the live connection followed by a verdict produces
`{"pending":…}{"deny":…}` in `resp`. `JSON.parse` throws. **grok and agy then exit 0 silently, which is
allow.** A streaming implementation would pass every Claude test and silently allow on two of the seven
engines. Do not let this plan be "simplified" into holding the connection.

**S-2 sequenced this after plan 04-10 for a reason, and there is a commit hazard to carry.**
`gitCommitter.ts:238-248`'s `harnessAuthored` byte-compares `bin/cth-hook.cjs` against the `HOOK_SHIM`
constant — *against the INDEX blob (`git show :path`), not the working file.* Changing the constant is
fine: `hive.ts:801` rewrites the file every bootstrap. **But the constant change and any regenerated
committed shim must land in the SAME commit, or the secret-scrub sees a mismatch and the false positives
it exists to suppress come back.**

**Pitfall 6 — the trap.** Flipping the shim's existing 5 s `setTimeout(() => process.exit(0), 5000)`
(`hiveTemplates.ts:347`) to a deny is the obvious way to make the wait fail closed. It would make **every
socket outage, every app restart, and every legitimately-not-running floor deny every tool call on every
agent.** The 5 s timer is untouched for the non-ask path.

**And there is a second, opposite trap, which the previous draft fell into by saying "replaces" without a
mechanism.** `hiveTemplates.ts:347` reads, literally,
`setTimeout(() => process.exit(0), 5000).unref();` — **the handle is discarded.** `.unref()` only stops
the timer from *holding the event loop open*; it does not stop it firing while the process is alive for
other reasons, and a poll loop is exactly such a reason. So a shim that receives `hive_ask` at t=0 and
polls a 120 s ask **exits silently at t=5s** — and a silent exit is ALLOW, which this plan's own text calls
*"the single most important line in this plan."* Saying the deadline "replaces" the timer does not replace
it. **`grep -n "clearTimeout" 04-16-PLAN.md` returned nothing in the previous draft; that is the defect.**

So, concretely and as task 1's first change: `const bootTimer = setTimeout(() => process.exit(0), 5000);
bootTimer.unref();` — capture it — and `clearTimeout(bootTimer)` on the branch that enters the poll loop.
Per-poll timers thereafter. The non-ask path never reaches the `clearTimeout`, so its budget is byte-for-byte
what it is today.

**The test that can see it must be written on purpose.** Task 2's other cases all complete in well under
five seconds — that is the point of the 10 s file budget — which puts every one of them *beneath the
threshold the bug lives at*. Production TTL is two minutes: a phone push plus a human tap. So task 2 carries
one case with a TTL of **~6 s**, deliberately over the boot timer and comfortably inside the file budget,
asserting a **non-empty deny** on stdout. Without it the suite is green and the first real 3am ask silently
allows at t=5s on every engine.

**Output.** A poll loop in one shim with its boot timer cleared, two shims left untouched, and the
integration test that observes every outcome — including the one that only a TTL longer than five seconds
can reach — on real stdout.
</objective>
