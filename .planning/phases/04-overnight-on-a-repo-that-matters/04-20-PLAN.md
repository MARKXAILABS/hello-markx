<objective>
The composition root. Four seams were declared in waves 2 and 4 as optional trailing constructor arguments
and nothing has supplied them. This plan supplies them, and proves it by booting a real floor.

**Purpose — this is the phase's one systemic defect, given its own plan because it deserved one.** The
red-team round found that `files_modified` had been verified for collisions but never for **completeness
against what each plan's own prose said it must change**, and `src/main/floor/boot.ts` — the sole
production construction site for every seam this phase adds — was in no plan's scope for any of them. The
consequence is specific and it is the shape D-28 already burned this project once: plan 04-06's host
allowlist, plan 04-15's `ApprovalRegistry` and its `recordToolCall` writer can all ship with green unit
tests, driven by `HookServer` instances the tests constructed themselves, while the floor an operator
actually runs has none of them. **Green and dead.**

**Why the seams are optional and trailing, and why that makes this plan necessary rather than redundant.**
`hooks.ts:554-561` states the house rule for a new `HookServer` dependency in its own words: *"Optional so
the server still runs without it, exactly like `breaker` and `control` above — and LAST, so no existing
call site or test has to move an argument."* There are **eight** `new HookServer(` sites across `src/` and
`test/`, most passing three to five positional arguments, and `test/hive-durability.test.cjs:186-193` pins
that `boot.ts` holds exactly one of them. Converting the constructor to a dep object would touch all eight
in the repo's most security-sensitive file for no requirement. So the seams are appended, optional — and
optional means **nothing fails if they are never wired**. That is exactly why the wiring needs an owner, a
wave, and a test that fails when it is missing.

**Why wave 5 and not earlier.** A declaration and its sole consumer cannot sit in two parallel plans: under
`use_worktrees: false` both edit one tree and whichever lands first sees the other's absence as a typecheck
error, and every plan in this phase carries `typecheck → 0 errors` as a hard criterion. Plan 04-06 declares
`hostAllowlist` and `openAsk` in wave 2; plan 04-15 declares `recordToolCall` and `publishApproval` and
supplies `openAsk`'s implementation in wave 4. Wave 5 is the first wave in which all four exist and
`boot.ts` has no other owner (plan 04-03 held it in wave 1, plan 04-09 in wave 2, plan 04-11 in wave 3).

**What is NOT here, and why.** `blocked` was wired at wave 1 by plan 04-03 — it is a **required**
`DeliveryDeps` member, so `boot.ts` fails typecheck until it is supplied, and typecheck pressure is a better
enforcement mechanism than a plan. `envPassThrough` rides `SpawnOptions` from `index.ts`'s
`spawnAgentCore` (plan 04-05, wave 1) rather than through a `PtyManager` setter, so it needs no
composition-root line at all. `src/main/floor/deps.ts` needs **no change this phase**: plan 04-08's ledger
writer reaches the hive through `deps.hive`, which `agentTeardownDeps()` (`boot.ts:254-261`) has always
carried. Plan 04-17 and plan 04-18 reach the approval registry through `floor.hookServer.openApprovals()`
and `.answerApproval()`, and `hookServer` has been a declared `Floor` member since Phase 2 (`boot.ts:102`,
re-measured in round 3) — so neither needs a `Floor` interface change either. Plan 04-11 added `watchdog`
to the same interface in wave 3, for the same reason, so plan 04-17's `floorQuiet` read and plan 04-18's
chip are both routed without a line here. All four of those are stated here so the next reader knows they
were considered rather than missed.

**Output.** Four arguments appended to the sole `new HookServer(...)`, and the boot test that fails if any
of them is dropped.

**Every line number in this plan is a wave-0 measurement and must be re-measured at wave start.** Plans
04-03 (wave 1), 04-09 (wave 2) and 04-11 (wave 3) all insert above the construction site; the previous
draft's `:1119` was already **off by one** at HEAD before any wave ran (`grep -n 'new HookServer(' ` →
**`:1120`** at `1faabe2`). Every acceptance criterion below is therefore stated as a **symbol boundary**
rather than a line window, and the prose figures carry a re-measure instruction. That is R3 rule 1 and it
applies to this plan more than to any other, because this plan is the furthest downstream.
