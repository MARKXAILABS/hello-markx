<objective>
VIGIL-03's **durable** half: stop the quiesce backstop flipping a blocked agent to idle, and stop the
wake nudge mailing it more work. This is a two-line guard plus a filter, in main, in a file with existing
tests, provable with a fake — and it is the half that actually fixes the bug.

**Purpose, and the correction that makes this plan exist.** `04-CONTEXT.md` D-28 says VIGIL-03 is
"half-shipped, and the shipped half is unreachable" — pointing at `stopArmDecision`
(`src/renderer/src/hooks/useHive.ts:169`), which returns a null patch when the event is `synthesized` and
the agent is already `blocked`. `04-RESEARCH.md` § Pattern 9 measured that it is **worse and simpler than
that**: Phase 2 moved the quiesce backstop into main, and the main-side loop calls
`this.deps.setStatus?.(a.agentId, 'idle')` at **`delivery.ts:740`** with **no blocked check whatsoever** —
it checks the breaker level (`:727`) and the boot grace (`:730`) and nothing else. `stopArmDecision` guards
only the *renderer's* reaction to the synthesized Stop emitted on the very next line (`:752`).

`setStatus` is documented at `delivery.ts:117-120` as *"the DURABLE half of a quiesce transition… this one
has to work with the window closed"*. So on a headless floor (Phase 2's `floor/headless.ts`) the guard
does not exist at all, and on a windowed floor the durable status is already `idle` before the renderer
gets a say. Then `tick()`'s wake nudge (`:770-806`) filters on `switching` (`:771`), `paused` (`:772`),
`vetoed` (`:773`), boot grace (`:774`) and `idleMs < IDLE_MS` (`:778`) — **and never on status** — so it
mails that agent more work.

**A plan that only fixes renderer detection ships a green test and an unchanged bug.** S-6 is binding:
guard first, detector second. The detector is plan 04-07.

**Output.** `blocked: boolean` on `LiveAgentPty`, a guard before `:740`, a wake-nudge filter, and two
tests that go red against today's source.
</objective>
