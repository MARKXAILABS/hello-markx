<objective>
VIGIL-03's **durable** half, plus the producer that makes it reachable: stop the quiesce backstop flipping
a blocked agent to idle, stop the wake nudge mailing it more work, and wire a real detector into the
production composition root in the same plan — because a guard whose producer lives in another plan's file
is a green test on a dead branch.

**Purpose, and the correction that makes this plan exist.** `04-CONTEXT.md` D-28 says VIGIL-03 is
"half-shipped, and the shipped half is unreachable" — pointing at `stopArmDecision`
(`src/renderer/src/hooks/useHive.ts:169`), which returns a null patch when the event is `synthesized` and
the agent is already `blocked`. `04-RESEARCH.md` § Pattern 9 measured that it is **worse and simpler than
that**: Phase 2 moved the quiesce backstop into main, and the main-side loop calls
`this.deps.setStatus?.(a.agentId, 'idle')` at **`delivery.ts:740`** with **no blocked check whatsoever** —
it checks the breaker level (`:727`) and the boot grace (`:730`) and nothing else. `stopArmDecision` guards
only the *renderer's* reaction to the synthesized Stop emitted on the very next line (`:752`).

`setStatus` is documented at `delivery.ts:117-120` as *"the DURABLE half of a quiesce transition… this one
has to work with the window closed"*. So on a headless floor (Phase 2's `floor/headless.ts`) the guard
does not exist at all, and on a windowed floor the durable status is already `idle` before the renderer
gets a say. Then `tick()`'s wake nudge (`:770-806`) filters on `switching` (`:771`), `paused` (`:772`),
`vetoed` (`:773`), boot grace (`:774`) and `idleMs < IDLE_MS` (`:778`) — **and never on status** — so it
mails that agent more work.

**`blocked` is a DEP, not a field on `LiveAgentPty`, and that is the revision's structural decision.**
The first draft added `blocked: boolean` to the `LiveAgentPty` interface and left the `liveAgents()`
literal at `boot.ts:1067-1072` — which supplies exactly six fields with no spread — to somebody else. That
shape is unbuildable two ways over: making the field required breaks `boot.ts`'s typecheck in a file this
plan did not own, and making it optional deletes the only pressure that would ever produce a producer, so
the guard ships reading `undefined` forever. `DeliveryDeps` already carries **`paused: (agentId: string)
=> boolean`** (`delivery.ts:101`, wired at `boot.ts:1079` to `control.isAutoDeliveryPaused`). `blocked` is
the same shape, for the same reason, wired the same way — and because a **required** dep on a dep object
this plan also owns the wiring for, the declaration and its supplier land together.

**The producer is real at wave 1 and costs no new state.** `PtyManager.outputTail(id)` already exists
(`pty.ts:930-933`), already returns the session's bounded ring, and — per `pty.ts:64-71`'s own doc —
*"recorded whether or not a renderer is listening."* So `matchBlockHint(outputTail(ptyId))` at the
composition root is a complete main-side detector with no cache, no latch and no new PTY state. The
recovery path is free: when the agent prints past the prompt, the recent window no longer ends in one and
the determination clears by itself.

**A plan that only fixes renderer detection ships a green test and an unchanged bug.** S-6 is binding:
guard first, detector second. Plan 04-07 (wave 2) makes it *one* list for two readers by deleting
`usePtyParser.ts`'s local copy and proving detection with no renderer module loaded.

**Output.** `blocked` on `DeliveryDeps`, a guard before `:740`, a wake-nudge filter, `src/shared/blockHints.ts`,
the production wiring at `boot.ts:1056-1117`, and two tests that go red against today's source.

/** Is this agent sitting on a prompt waiting for a human?

 *  REQUIRED, not optional, and the difference is the whole of VIGIL-03. An agent
