<objective>
GATE-05's main-side half — the third answer, its registry, its bounded wait — plus RECORD-01's writer,
which belongs on this same seam and in this same file.

**Purpose — D-01, and why these are one plan.** `ControlRegistry.toolDecision(id, tool)`
(`src/main/control.ts:97`) is the only per-tool-call verdict in main. It is **synchronous**, it returns
`{ deny: boolean; reason?: string }`, and it inspects only `paused` and `gatedTools` — it never sees the
command string. GATE-03 (plan 04-06) taught main to judge the string; GATE-05 needs that judge to have a
third answer. S-1: *"GATE-05's third answer is a third return value from the judge GATE-03 builds; there
is nowhere for 'ask' to hang until 'deny for this shape' exists."*

**Pattern 3 is the design, and it is decided by a measurement, not by taste.** RESEARCH § L-02:
`GROK_HOOK_SHIM` runs `JSON.parse(resp || '{}')` over the **whole accumulated buffer**
(`hiveTemplates.ts:772`); on a parse failure it sets `out = null` and `process.exit(0)` **with no
stdout — which is allow**. `AGY_HOOK_SHIM` has the same shape. Two JSON objects concatenated on one
connection is a parse failure. **So a held-open connection with a "pending" preamble is a silent
fail-OPEN on two of the seven engines.** It would pass every Claude test. That rules out the streaming
form regardless of how attractive it looks, and it is why the shims **poll** (plan 04-16).

**The reply shape that makes this work without version negotiation.** One object, two readings: an old
shim sees only `hookSpecificOutput` and denies; a new shim sees `hive_ask` and polls instead. Old shim →
**deny**. Fail-closed on the correct side, for free.

**D-08's three clauses, all of which this plan must hold simultaneously:**
1. allow and deny behave exactly as today; the shim's 5 s budget is untouched for them;
2. only on **ask** does a longer wait begin, defaulting to **deny** on expiry;
3. **a socket that is gone, refuses, or answers nothing still exits 0 = allow.** Fail-open is preserved
   for *"the floor is not running"*; fail-closed is introduced only for *"the floor asked and the operator
   did not answer"*. Those are different failures and must not share a default. The connect-error path is
   reached **before** any `hive_ask` is ever seen, so clause 3 holds by construction.

**RECORD-01 rides here, and the reason is measured.** RESEARCH § Pattern 4 / L-05 killed D-17's literal
reading: `ToolSpan` has no `target` field, `ATTR_ALLOWLIST` admits no path or command key, and the whole
OTel path is `if (claudeProvider && …)`. The data lives on the hook socket — `HookPayload`
(`hooks.ts:86-116`) carries `tool_name` and `tool_input`, `protectedPathDenial` already reads `file_path`,
`path`, `notebook_path` and `command` out of it at `:865-889`, and `agentId` comes from `authorized()`
(`:626`), i.e. **GATE-01's guarantee is already applied before the writer sees anything.** `hooks.ts` has
one owner per wave and this plan is it; putting the writer anywhere else would take a fifth wave.

**Output.** `approvals.ts`, `control.ts`'s third answer, `hooks.ts`'s ask reply + poll branch + record
writer + GATE-05 ceiling.

<planner_decisions>
The two numbers CONTEXT.md explicitly left open (D-08: *"the two-phase shape is locked, the numbers are
not"*), decided here and reconciled against each other as D-08 requires:

**There is a FOURTH deadline, it is the outermost one, and the first draft did not name it.** D-08's own
words are *"a plan that changes one number without the other ships a gate that times out on the wrong
side."* There are four numbers, not three. The engine's own PreToolUse hook timeout is the outermost bound,
and every value in the repo today is shorter than a 120 s ask:

| Engine | PreToolUse hook timeout today | Source | vs a 120 s TTL |
|---|---|---|---|
| grok | **~5 s** — no `timeout` key is written, so grok applies its event-aware default | `hiveProvisioning.ts:415-426` (`tool()` emits `hooks: [{ type:'command', command: nodeRun(shim) }]`, and the comment at `:424-425` says *"Let Grok apply its event-aware defaults (5s normally, 600s for Stop)"*) | 24x short |
| codex | **30 s** | `hiveProvisioning.ts:232` (`timeout = 30`, seconds — see the long note at `:210-223`) | 4x short |
| kimi | **30 s** | `hiveProvisioning.ts:293` (`timeout = 30`) | 4x short |
| agy | `timeout: 0` | `hiveProvisioning.ts:128` and `:131` | semantics unknown; agy is not installed |
| Claude | engine default | `hookSettings` | unreconciled |

`hiveProvisioning.ts:214-219` records what happens when the bound is exceeded, in this repo's own words:
the hook is killed and logged as **failed**, not denied. **A killed shim writes no stdout, and no stdout is
ALLOW.** So GATE-05's "times out to deny" becomes "times out to allow" on the ordinary path, on every
engine, silently, with every test green.

**The fix, and it moves both numbers together because that is the whole of D-08.** Introduce ONE constant
in `hiveProvisioning.ts`, beside the values it writes:

```ts
/** PreToolUse only. Every other event keeps its existing budget — widening them
 *  costs latency on paths that have no verdict to wait for. [ASSUMED]: no
 *  measurement in this session supports 150; it is the smallest round number that
 *  leaves ASK_TTL_MS a workable phone-approval window with margin. */
export const PRETOOLUSE_HOOK_TIMEOUT_SEC = 150;
/** The server-side ask TTL, DERIVED so the two cannot drift. The 30 s margin covers
 *  shim cold-start (hiveProvisioning.ts:216-218 measured 0.6-0.7 s under 8 concurrent
 *  spawns) plus the final poll round trip. */
export const ASK_TTL_MS = (PRETOOLUSE_HOOK_TIMEOUT_SEC - 30) * 1000;   // 120_000
```

Codex's own resolver defaults to 600 s when the key is omitted (`hiveProvisioning.ts:212`), so 150 is well
inside its bounds; the note at `:222-223` names the no-spend way to verify it (`codex app-server` →
`initialize` → `hooks/list` reports the normalized `timeoutSec`). **A wedged shim is still bounded** — its
own per-poll 5 s timer and `deadlineMs` both fire well before 150 s; the engine timeout is only the outer
backstop.

`ApprovalRegistry` takes `ttlMs` as a constructor option so it stays dependency-free; the production value
is `ASK_TTL_MS` and plan 04-20 passes it. **Assert the relationship in a test**, not in a comment:
`ASK_TTL_MS <= PRETOOLUSE_HOOK_TIMEOUT_SEC * 1000`, both read from the module.

| Bound | Today | Under GATE-05 | Why |
|---|---|---|---|
| **Engine PreToolUse hook timeout** | 5 s (grok) / 30 s (codex, kimi) / `0` (agy) | **`PRETOOLUSE_HOOK_TIMEOUT_SEC = 150` for codex, kimi and grok's PreToolUse only** | The outermost bound. Below the TTL it kills the shim, which writes no stdout, which is ALLOW |
| `HOOK_IDLE_MS` (`hooks.ts:446`) | 2 000 ms | **unchanged** | It bounds *framing*, not decisions; every poll is a fresh short connection well inside it |
| `HOOK_SHIM` exit timer (`hiveTemplates.ts:347`) | 5 000 ms → allow | **unchanged for the non-ask path**; armed per-poll-connection, and replaced by `deadlineMs` → **deny** once `hive_ask` is seen | The 3 s margin `hooks.ts:440-445` reasons about is preserved exactly |
| **Ask TTL (new)** | — | **`ASK_TTL_MS` = 120 000 ms**, `[ASSUMED]`, **derived from the row above** | Long enough for a phone push to arrive and be tapped; short enough that a worker is not wedged for a coffee break. Derived rather than written as a literal so the two cannot drift — D-08's requirement, applied to the pair that actually binds. |
| **`deadlineMs` handed to the shim** | — | `openedAt + TTL` | **The server-side TTL must be ≤ this**, or an operator's late "yes" answers a question whose asker already denied and moved on |
| **`pollMs`** | — | **1 000 ms** | One connection per second per pending ask; there is at most a handful of those at a time |

Do not change one number without the other. A plan that adjusts the TTL and not the deadline ships a gate
that times out on the wrong side.
